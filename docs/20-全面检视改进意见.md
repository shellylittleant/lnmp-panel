# 20 全面检视改进意见

> 记录日期：2026-09-22
> 状态：已取舍并实施（2026-09-22）。取舍记录见 `reviews/grok/阶段10-审核.md` 第 3 节；未采纳：登录失败提前占名额、热备令牌混用（未找到路径）。H6 按需求方选第二个选项，H7 立刻执行统一为 shell，CLONE 删除而非修复。
> 来源：对 `work/grok`（`main`，`def71a4`）的全树检视。没有远端基线，不是某一次提交的增量审查。
> 范围：鉴权、文件与防火墙、站点与证书、热备与 MySQL、定时任务与日志、前端。最高风险项已对照源码复核。

界面结构不用重做。十项主菜单、安装集中在「环境安装」、迁移和热备放在同一页，这些和 [14-界面结构.md](14-界面结构.md) 一致。要改的是：按钮的实际效果必须和文案一致，成功提示必须和磁盘、数据库一致，危险操作在点下去之前把后果写清楚。

备机已经死掉时仍允许提升，这是容灾该有的行为，不列入缺陷。

## 一、整个界面

**会话失效要立刻离开后台。** 现在只有打开外壳时查一次登录。过期之后菜单和用户名还在，各页把「未登录」当成普通红字，保存按钮仍能点。应在所有请求里统一处理 401：清掉内存里的 CSRF，回到登录页。退出要等接口成功再跳；失败就留在当前页并说明 Cookie 还在。日志跟随断线时也走同一条，不要停在「正在跟随」。

**成功只表示这次提交真正写进去了。** 多处是后端把空值当成「不修改」，界面却提示已保存。站点改成静态、清空模板、清空域名都是这样。保存后用接口返回的记录回填表单，不要用点击前的本地状态宣布成功。

**危险操作用同一套确认，文案写后果，不写按钮名。** 现在删站、删库、删用户、覆盖证书、启用主模式、降级、改防火墙都是一点就执行。确认框至少写明：会删什么、会不会动网站文件、会不会立刻改内核防火墙、MySQL 会变成可写还是只读、站点会变成维护页还是 404。备机顶部已经有一条「配置由主机同步」，但防火墙、设置、装 MySQL、轮转这些在备机上仍能保存。要么这些按钮在备机上禁用并说明原因，要么这条横幅改成「部分设置仍可在本机修改，且不会被主机覆盖」。

**长时间任务不要把「还在跑」说成失败。** 安装和导入 SQL 最多等大约 6 分钟就报超时，按钮随即可再点，后端却仍占着同一个任务。超时文案应说明可能仍在执行，并继续用原来的任务编号查询。离开页面后停止轮询。

## 二、各页

### 迁移与热备

「完成迁移」和「取消并作废钥」现在是同一个取消接口。进行中点「完成」会中止任务并作废临时钥。删掉「完成」，或只在任务已经成功时提供「作废临时钥」，并且不要写成完成。

启用主模式、降级、配对要在确认框里列出三件事：本机和对端的 MySQL 读写、Nginx 是正常站点还是 404 或维护页、防火墙会立刻加载且不进入 60 秒确认。对端联系不上时可以继续提升，这是容灾需要的，但必须写明「对端可能仍在对外服务」。进度请求失败时不要留着上一次的阶段，让人以为还能再点全量同步。

### 网站

静态站点要提交空字符串，不能提交 JSON `null`。模板和域名的「清空」要和「这次不改」分成两个值。详情里补上文档要求的 301 列表；原文模式下按后端拒绝规则把表单禁用。已有证书时，「申请」和「手动导入」都要说明会删掉当前证书并马上改 Nginx。删除站点要写明：Nginx 配置和证书会删，网站目录默认保留。列表上的「启用」列应接到已有的启用、停用接口。模板库要能新建、删除、导入、导出，不要只能改一条已有模板。

### 防火墙

表单上没画出来的字段不能在保存时被清掉。加载时带上全部 SSH 端口和 UDP 端口，保存时原样交回；或者把这两列画出来。文档里的「封禁」要有入口，解封也一并做，如果后端已有对应能力。应用之后的倒计时要始终在，回滚失败不能把倒计时取消掉。热备切换若绕过这个窗口，确认框里必须单独写一句。

### 日志

「保留天数 / 单文件上限」和原文编辑分成两个按钮。表单保存不要把当前原文一并提交，否则天数改了、磁盘上的轮转文件不变。跟随在 401 或日志源不存在时要停，不要一直显示正在跟随。

### 文件

一次选择多个文件时，只上传这一次新增的，传完清空列表；覆盖确认只针对这一批，不能把已经传过的再传一遍。切换目录时丢掉上一次的勾选，过期的列表响应不能覆盖当前目录。压缩不要固定写成当前目录的 `archive.zip` 并无声覆盖；目标名可改，已存在时走和复制一样的确认。删除确认里写出路径，不要只写数量。面板自己的密钥目录继续拒绝，并在点到时说明该走 SSH，而不是等到请求失败。

### 数据库

删库、删用户、导入 SQL 都要二次确认，并展示完整库名或 `user@host`。删库不要复用「导入导出的库名」那个自由输入框，应从表格当前行取。导出要先看状态码，失败时不要下载一个残缺的 `.sql`。改用户密码的接口已经有了，页面上没有。

### 定时任务

删除前确认任务名和将要写回的命令。到点执行和「立刻执行」如果安全限制不一致，界面上不要让人以为立刻执行被拒绝的命令，到点也不会跑。

### 设置

补会话列表：来源地址、浏览器、创建和过期时间，以及踢下线。踢掉当前会话后走和 401 一样的清理。开启或关闭 TOTP 后应要求重新登录，关闭时再要一次当前验证码。只改密码才踢其他会话，第二因素可以留着旧会话，这个差别用户看不出来。

### 概览

保持现在的分工：未安装只给「去环境安装」，不要把安装按钮放回网站、PHP 或数据库页。备机、降级、防火墙待确认这三种状态适合做成概览上的醒目卡片，因为它们决定了别的页能不能改。

## 三、界面要靠后端一起改

这些不是换文案能解决的。界面做对了，下面不改，仍会保存成功但机器状态是错的。

| 编号 | 位置 | 意见 |
|---|---|---|
| H1 | 防火墙确认窗口 | 回滚必须先加载备份成功，再取消倒计时。加载失败就保留倒计时。规则已经放进内核、数据库却没写上待确认记录时，立刻用备份加载回去。 |
| H2 | 文件解压与权限 | 解压不要把目标目录里原有文件一律改成 `0644`，也不要跟着符号链接写到目录外。非递归改权限也要拒绝密钥的父目录。 |
| H3 | 站点与证书 | `reload` 失败不能用「服务已经在运行所以 start 成功」当成新配置已生效。站点、域名、跳转和证书要在 `nginx -t` 成功之后再落库。续期不要用旧表单覆盖手改过的配置。证书和私钥要配对替换，不要分两次留下不匹配的文件。更新 PHP 版本要走和创建时相同的版本号校验。 |
| H4 | 热备与复制 | 降级必须等对端只读成功才算成功。空证书指纹拒绝配对。热备令牌不能当迁移令牌用。复制账号限制到对端地址，不要 `'%'`。`CLONE INSTANCE FROM` 的主机名要加引号。 |
| H5 | 登录与 TOTP | 登录失败次数要在校验密码之前占名额。口令正确但还要 TOTP 时也要限流。验证码用过即失效，开、关 TOTP 都使旧会话失效。关闭 TOTP 时除了口令再校验当前验证码。 |
| H6 | 备机写保护 | 备机上拒绝防火墙、设置、安装、轮转、插件这些写操作，或者同步时把它们也算进主机覆盖的范围。现在的横幅和实际权限不符。 |
| H7 | 定时任务与调度 | `crontab -l` 失败不能当成空表再覆盖 root 的整份 crontab。到点执行走 shell，立刻执行走拒绝名单，两边不要让界面暗示成同一套限制。调度器在开始跑之前注册全部任务，包括迁移公钥过期清理。 |
| H8 | 安装任务 | 面板被杀掉后，未完成的安装任务要标成失败或允许接管，不能永远占着「已有同类任务在执行」。官方源写入之后若发现是 MariaDB，任务失败时删掉刚写下的源和密钥。 |

## 四、建议的落地顺序

界面文档里已经有、后端也有、只差页面的，是 301、封禁和会话列表。建议先做这三处，再加上「完成迁移」按钮和会话过期处理。其余危险操作的确认框可以同一批加上。

后端按这个顺序：防火墙确认窗口和密钥权限（H1、H2），热备双主与复制账号（H4），TOTP（H5），再是 Nginx 的假成功和那几个会静默写错的表单（H3，以及第二节里网站、防火墙、日志的保存语义）。

## 五、不改

| 项 | 说明 |
|---|---|
| 十项主菜单和「环境安装」的位置 | 与 docs/14 一致。未安装只链到环境安装，不把安装按钮放回功能页。 |
| 备机不可达时仍允许提升 | 容灾需要。确认框写明对端可能仍在服务即可。 |
| 定时任务可以包含 shell 元字符 | 面板不限制服务器上本来能做的事。要改的是立刻执行和到点执行的不一致，以及 `crontab -l` 失败覆盖其他任务。 |
| 全目录文件管理 | 仍允许操作全目录。要收紧的是密钥权限被解压或 chmod 放宽，不是把文件管理缩回 `/var/www`。 |
