# 05 防火墙方案对比

> 记录日期：2026-09-16
> 状态：已决定用 **nftables 直接操作**，2026-09-16

## 背景

Ubuntu 22.04 起内核防火墙统一是 nftables。ufw 是 Ubuntu 官方提供的一个**命令行前端**，它把简单命令翻译成规则，最终也落到 nftables。所以两者不是两套防火墙，而是"直接操作底层"和"通过简化封装操作底层"的区别。

## 对比

| 维度 | ufw | nftables 直接操作 |
|---|---|---|
| 定位 | Ubuntu 官方的简化前端 | 内核原生防火墙本体 |
| 上手 | 一条命令一条规则，例如 `ufw allow 80/tcp` | 需要理解表、链、规则集的层次，语法较重 |
| 表达能力 | 基础：开关端口、按 IP 允许/拒绝、简单限速 | 完整：IP 集合（几万个黑名单 IP 也高效）、限速、按连接状态、计数器、地理封禁等 |
| 规则存储 | 分散在 `/etc/ufw/` 多个文件，格式是它自己的 | 单一文件 `/etc/nftables.conf`，原子加载，改错了整体回滚 |
| 与面板"模板"理念的契合 | 差：ufw 自己管理规则文件，面板不好用模板覆盖 | 好：面板从模板生成整个规则集文件，一次性加载 |
| 与"SSH 能做的面板都要能做"的契合 | 差：ufw 只暴露底层能力的一个子集，超出的部分要绕过它 | 好：没有天花板 |
| 流量计数与日志 | 弱 | 原生计数器，方便做统计（对接日志监控模块） |
| 与其他写规则的工具冲突 | ufw 和 Docker、fail2ban 之间有著名的冲突问题 | 面板独占规则集，其他工具不得再写，需要明确约定 |
| 面板实现难度 | 低：封装几条命令 | 中：面板要自己维护完整规则集的生成与校验 |

## 我的建议

**直接操作 nftables。** 理由有三：

1. 你的核心理念是"面板不设限"，ufw 天生是一个子集，迟早会碰到天花板。
2. "单一文件 + 模板生成 + 原子加载"与你的模板机制完全一致。
3. 面板独占规则集，反而比 ufw 更容易避免多工具互相覆盖的混乱。

代价是面板要自带一套规则集的可视化表单，但你需要的规则种类本来就不多，形态固定。
