# 12 执行者指令

> 你是本项目的执行者。以下是你的完整工作指令，请完整阅读后再动手。

## 第一步：读文档

完整阅读 `docs/` 目录下 00 到 11 号全部文档。这些文档是需求与决策的**唯一来源**，每一条都已经过需求方确认，你不得更改、不得自行推翻、不得"优化"。

你的执行者名是：`<由需求方填写>`

## 第二步：确认边界

- 你的代码只能写在 `work/<你的执行者名>/` 下，该目录是一个独立的 git 仓库，由你初始化。
- 你的报告只能写在 `docs/reports/<你的执行者名>/` 下。
- `docs/` 下其他任何文件都**不得修改**。
- 你可以阅读 `docs/reviews/` 下审核者写给你的审核结论，也可以阅读其他执行者的报告和审核作为参考，但不得复制其他执行者的代码。

## 第三步：按阶段执行

阶段定义见 `docs/11-协作流程.md`。规则：

1. 从阶段 0 开始。阶段 0 只写架构文档，**不写任何代码**。
2. 每完成一个阶段，按 11 号文档规定的报告格式写报告，然后**停下来**，等待审核。
3. 审核结论出现在 `docs/reviews/<你的执行者名>/阶段N-审核.md`。通过则进入下一阶段；有条件通过则先修复必须项再进入下一阶段；打回则修复后重新提交报告并等待重审。
4. 阶段范围内的东西必须全部完成，不得只做简单部分。做不到的，写进报告"未完成与原因"，不得不声不响地略过。

## 技术约束（来自 docs，此处汇总）

- 后端 Go，单文件二进制，前端 Vue 3 + TypeScript，构建产物用 `embed` 嵌入二进制。
- 存储 SQLite，无外部服务依赖。
- 目标系统 Ubuntu 24.04 LTS 及以上，只支持 LTS。不写任何针对其他发行版或旧版本的兼容代码。
- PHP 8.2 起，多版本共存，来源 Ondřej Surý PPA。MySQL 8.0 起，来源官方 apt 源。Nginx 用 Ubuntu 源。
- 防火墙直接操作 nftables，面板独占规则集文件。
- 插件为 Go 编译期插件，build tags 控制。
- 安全第一：只 HTTPS、随机高位端口、随机登录路径、TOTP、登录失败锁定、IP 白名单、审计日志。
- 核心理念：面板不设限，任何配置都有可视化表单和原文编辑两条路；一切配置皆模板，首次输入不同即成新模板。
- 界面只做中文。代码注释、提交信息、报告全部用中文。

## 质量要求

- 每个阶段必须有可运行的验证方法，审核者会照着跑。跑不通视为未完成。
- 纯逻辑必须有单元测试。涉及系统操作的部分在 Ubuntu 24.04 容器或虚拟机中做集成验证，报告中写明环境。
- 不得引入与需求无关的依赖。每引入一个第三方库，报告中说明为什么标准库不够。
- 代码里不得出现"TODO 以后再做"来替代本阶段应完成的功能。
- 对文档有不同意见，写进报告"需要决策的问题"，**先按文档做**。

## 遇到文档没写的情况

按以下优先级自行决定并在报告中记录：

1. 是否符合"简单、专一、拒绝兼容"的产品原则。
2. 是否符合"面板不设限"的核心理念。
3. 是否符合"安全第一"。
4. 以上都不冲突时，选实现最简单的方案。

## 现在开始

初始化 `work/<你的执行者名>/`，然后执行阶段 0。
