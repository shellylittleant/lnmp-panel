## 1. 完成内容

### 1.1 角色与任期

| 要求 | 落点 |
|---|---|
| `standalone` / `master` / `standby` | 表 `ha_state`（`008_stage7.sql`），任一时刻只有主机可写 |
| 任期单调递增 | 备机「启用主模式」时 `term = term+1` |
| 自我保护比 term | `ShouldDegrade`：本机曾是 `master`、对端可达且对端 `master` 且 `peer.term > local.term` 才降级；联系不上不做猜测 |

### 1.2 配对复用阶段 6，热备长期有效

- `POST /ha/token`：令牌格式与迁移相同（指纹前 16 位 + 随机），`pairing_tokens.purpose='ha'`。
- 备机 `POST /ha/pair {address, token}`：校验 TLS 指纹后握手。调用方成为 **备机**，对端成为 **主机**。
- 双向长期 SSH 钥：`/var/lib/lnmp-panel/secrets/ha-key`，授权段 `# LNMP-PANEL-HA-BEGIN/END`，与迁移段分离。
- 握手后交换机器令牌 `ha_machine_token`，供 `/ha/peer-role`、`/ha/health`、`/ha/peer/*` 使用（Header `X-LNMP-Peer-Token`，不走 Cookie/CSRF/IP 白名单）。
- `migrate.ExpireStale` 只删 `purpose=migrate` 的令牌，**7 天过期对热备不生效**（单元测试 `TestHATokenSurvivesMigrateExpire`）。

### 1.3 拉模型同步

备机发起，主机不推。

| 数据 | 方式 |
|---|---|
| 站点文件 | 备机 rsync over SSH（`ha-key` + known_hosts，`StrictHostKeyChecking=yes`） |
| 证书 / nginx `sites-available` / conf.d | 同上；`sites-available` 排除兜底 conf，避免 `--delete` 拆掉 404 软链 |
| 配置元数据 | 备机 `POST /ha/peer/bundle` 拉迁移 bundle，`ApplyConfigPull` 不改防火墙、不启用站点 |
| MySQL | 备机连主机 3306，GTID 复制。首次无 `GTID_EXECUTED` 时先 clone，失败则 SSH `mysqldump -uroot --all-databases --set-gtid-purged=ON` 再导入；已有 GTID 时只 `CHANGE REPLICATION SOURCE ... SOURCE_AUTO_POSITION=1`（回切不重导） |

自适应间隔：目标 60 秒，一轮结束才下一轮；一轮超过目标则间隔 = 耗时 + 10 秒；超过 5 分钟界面告警。inotify 后期。

### 1.4 备机 nginx 404

官方模板 `nginx_catchall_404`「备机 404」。`sites-enabled` 只留该兜底；站点 conf 只在 `sites-available`。提升为主时按库中 `enabled` 批量建软链。

### 1.5 防火墙模板

- 主机：官方「主机默认」另放行对端 IP 访问 SSH / 面板 / 3306。
- 备机：官方「备机白名单」：80/443 对公网；面板对运维 CIDR + 主机 IP；SSH 对运维（运维白名单为空时仍放行 SSH/面板以免锁死）。
- 角色切换时写入草稿与 `/etc/lnmp-panel/nftables.conf` 并尝试 `nft -f`。无特权容器里 `nft -c` 失败只记 `firewall_warning`，不阻断热备。

### 1.6 systemd drop-in

进入 `master` 时写 `/etc/systemd/system/{nginx,mysql,mysqld}.service.d/lnmp-panel.conf`：`After=lnmp-panel.service`。降级为备或退出 HA 时删除。无 systemd 时只落盘。

### 1.7 人工按钮与自我保护

| API | 说明 |
|---|---|
| `GET /ha/status` | 角色、term、间隔、落后、复制、nginx 模式、是否自我保护 |
| `POST /ha/promote` | **启用主模式**：停同步、停复制、MySQL 可写、启用站点 |
| `POST /ha/demote` | **降级为备**：404、只读、去掉 drop-in |
| `POST /ha/sync/start` | 仅备机开始拉 |
| `GET /ha/sync/status` | 同步状态 |
| `GET /ha/health`、`GET /ha/peer-role` | 机器令牌，供对端查询 |

无自动接管、无 DNS API。

启动自我保护（`app.Run` 在听端口之前）：本地记录「我曾是主机且备机是 B」则问 B；B 说自己是主且任期更大，则本机 MySQL 只读、站点改维护页（503，页面在 `/var/www/.lnmp-panel-ha`，避免 `/var/lib/lnmp-panel` 0700 导致 nginx 403）。联系不上按原状态启动。

备机不申请证书（`ssl.AllowIssue` 在 standby 返回 false）。

## 3. 与文档的偏离

| 点 | 说明 |
|---|---|
| 全库 dump 后面板 MySQL 账号 | dump 含 `mysql.user`。导入用 `mysql -uroot`，再按本机 `mysql-panel.cnf` 恢复 `lnmp_panel`。复制用户密码 ≤28 字符（MySQL ERROR 3056 上限 32） |
| 回切不重做全量 dump | 原主机已有 `GTID_EXECUTED` 时只建反向复制，避免 `GTID_PURGED` 重叠（ERROR 3546） |
| 维护页路径 | 不用 `/var/lib/lnmp-panel`（目录 0700，nginx worker 读不到会 403），改 `/var/www/.lnmp-panel-ha` |
| rsync 远程源 | 拉模型源是 `user@host:path`，不再对远程路径做本地 `Stat`（否则会静默跳过） |
| 无特权 nft | 与阶段 6 防火墙「写文件、确认窗口」一致；热备仍写出对应官方模板 |

未引入新 Go 模块。
