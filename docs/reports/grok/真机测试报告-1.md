### 3.3 首次失败原文（产品问题）

站点在 2.7 进入原文模式后，`PUT php_version=8.3` 返回：

```
{"error":{"code":"conflict","message":"站点处于原文模式，请先恢复为模板渲染"},"ok":false}
```

`POST .../nginx/use-template` 返回 ok，但 **磁盘 conf 仍是用户模板 id=18 的静态站**（`index index.html; try_files ... =404;`，无 `fastcgi_pass`）。此时 `index.html` 仍在，curl 200 看到的是欢迎页而非 phpinfo。删 `index.html` 后变成 **403**（目录索引关闭且无 html）。

`UseTemplate` 只把 `raw_mode=0` 再 `apply`，**不会把 nginx_template_id 从用户切片改回官方 PHP 模板**。删站重建并指定 `php_version=8.3` 后 conf 正确：

```
index index.php index.html;
fastcgi_pass unix:/run/php/php8.3-fpm.sock;
```

### 5.10 reboot 时序与缺陷

- 触发：`2026-09-16T23:11:20+08:00`
- SSH 恢复：`23:11:43`（约 **23 秒**，`uptime 0 min`）
- nft 持久化完整：

```
policy drop
tcp dport 22 accept comment "ssh"
tcp dport 26968 accept comment "panel"
tcp dport { 80, 443 } accept
```

- `nginx`/`php8.3-fpm`/`mysql`/`sshd`/`lnmp-panel` 均为 active；80/443/22/26968/3306 在听。
- **缺陷**：reboot 后 **无前缀** `https://IP:26968/` 立即 404；**带前缀** TLS 握手成功，但 `GET /{prefix}/` **无 HTTP 响应**（curl 5–8s timeout，exit 28）。`systemctl` 显示 active。对 `panel.db` 做 `PRAGMA wal_checkpoint(TRUNCATE)` 并 `kill -9` 后再 `systemctl start`，前缀立即 **200** 且登录 API 正常。
- 推测：`database/sql` `SetMaxOpenConns(1)` + WAL，启动后某后台任务占用唯一连接，所有走 `withSecurity`→`IPAllowed`→SQLite 的请求卡住；根路径 404 不查库所以正常。
- 公网盒子打前缀：白名单命中时 200；未命中 403；面板卡住时 timeout。测试结束前缀在 **localhost 200 + 登录 ok**；盒子出口偶发 timeout（不要反复打以免再次占死连接）。

## 建议打回 / 产品问题

1. **站点 `use-template` 不换回官方 PHP 模板**（3.3）：原文模式用户模板会留下无 PHP 的 conf；仅清 `raw_mode` 不够。
2. **默认 `index.html` 挡住 `index.php`**：即使用 PHP 模板，欢迎页仍优先；指南「写 phpinfo」在未删 html 时看不到。
3. **reboot 后面板前缀/API 卡死**（5.10）：TLS 通、GET 无响应；WAL checkpoint + 杀进程可恢复。单连接 SQLite 值得修。
4. **`systemctl restart` 常 5s `context deadline exceeded` 失败退出**（Shutdown 5s vs WriteTimeout 5min）。
5. **运维白名单**：egress NAT 一变即 403；localhost 也受 CIDR 限制（`127.0.0.1/32` 必须显式加入）。
6. **5.11 / 5.6 公网新连接** 未用第二出口验证，避免锁 SSH。
