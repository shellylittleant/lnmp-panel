## 四、产品问题 / 注意事项

1. **HA 配对写入 peer 主机名而非接入 URL 中的 IP**  
   A 的 `peers.address` / status 出现 `https://VM-0-10-ubuntu:22349/…`。故障恢复时若 DNS 无法解析该主机名，会「按原状态启动」而**检测不到对端已是 master**，也不会挂维护页。建议：持久化配对时使用用户填写的 URL 主机部分（IP/域名），或同时写入公网可达地址。

2. **`systemctl start lnmp-panel` 在对端不可达时不会拉起 nginx/mysql**  
   H11 首次仅面板 active，需手工 `systemctl start mysql nginx`（或修好 peer 地址后重启面板）。

3. **增量同步 API mode 值为 `incr`**  
   传 `incremental` 返回：`mode 只能是 full 或 incr`。目标已有站点时需 `confirm_replace:true`。

4. **全量迁移提示缺 PHP 8.2**  
   即使业务站点用 8.3，仍提示需装 8.2（来自源机已装版本清单）。PHP 8.2 在 B 上 install job 曾报 `php8.2-fpm.service is not active, cannot reload`。

5. **热备初次同步**  
   clone 不可用时回退全库导出；可能出现短暂 SQL 线程错误（errno 1396）后重试成功。面板 `mysql_repl_ok` 以最终轮询为准。

6. **备机 catchall 仅 80→404**  
   不监听站点 443 属预期；用 HTTP 访问 B IP 即可验证 H5。

7. **会话绑定客户端 IP**  
   经多出口 NAT 调用面板 API 易 401；真机自动化建议本机回环或固定出口。
