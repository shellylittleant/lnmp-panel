# 01 模块划分

> 模块是编译期的 Go 包边界，也是阶段交付边界。官方核心始终编进二进制；官方插件用 build tags，运行时可停。

`template`、`store`、`exec` 被几乎所有领域模块依赖，本身不依赖领域模块。

## 2. 基础设施（阶段 1 必须落地）

| 模块 | 包路径 | 职责 | 不做什么 |
|---|---|---|---|
| app | `internal/app` | 进程入口组装：读引导配置、打开 DB、注册模块、起 HTTPS、接信号退出 | 不写业务规则 |
| store | `internal/store` | SQLite 打开、迁移、事务。对外只暴露仓库接口 | 不写 SQL 散落在 handler |
| exec | `internal/exec` | 命令白名单执行、超时、stdout/stderr 采集、审计用摘要 | 不 `sh -c`；不直接暴露给前端 |
| fs | `internal/fs` | 写文件、写前备份、原子 rename、权限、读哈希 | 不解析 conf 语义 |
| auth | `internal/auth` | 管理员、密码、TOTP、会话、失败锁定（`ip_locks` 应用层）、IP 绑定、踢会话。阶段 4 起对非运维 IP 调用 firewall `login_ban`；**运维白名单 IP 永不写 nftables 封禁** | 不做 OAuth、不多用户 |
| audit | `internal/audit` | 记录所有写操作；只追加 | 不提供删除 |
| http | `internal/http` | TLS、前缀剥离、路由、中间件、错误信封 | 不拼业务 SQL |
| settings | `internal/settings` | 面板设置读写（端口展示、bind、白名单、保留期等） | 改端口/证书后需重启的，写明并提供重启动作 |
| scheduler | `internal/scheduler` | 进程内调度：证书续期、日志统计、热备 rsync 轮次、备份窗口预留 | 不替代用户 crontab（用户 crontab 归 cron 模块） |
| plugin | `internal/plugin` | 注册表、启用状态、钩子分发、页面声明合并 | 阶段 8 前只留注册与空分发，核心模块先按接口形状注册 |

## 3. 领域模块

| 模块 | 包路径 | 阶段 | 职责 | 依赖 |
|---|---|---|---|---|
| template | `internal/template` | 1 建表与官方库嵌入；2 起真正用于 nginx | 模板存取、哈希、渲染、自动建用户模板 | store, fs |
| env | `internal/env` | 1 做 OS 检查与 Docker 拒绝；**2 安装 Nginx**；**3 安装 PHP PPA 与 MySQL（按架构分源）** | 检测 Ubuntu LTS；检测到 Docker 则拒绝安装/启动并提示卸载；不装 Apache | exec |
| site | `internal/site` | 2 | 站点 CRUD、根目录、域名唯一、启用停用、绑定 PHP 版本与各模板 | template, nginx, php, fs |
| nginx | `internal/nginx` | 2 | 生成/读回 server 块、`nginx -t`、reload、全局片段、备机 404 模式 | template, exec, fs |
| ssl | `internal/ssl` | 2 | ACME HTTP-01 申请与续期、证书落盘、到期调度。主机申请，备机只收同步件 | exec, fs, nginx, scheduler |
| php | `internal/php` | 3 | 多版本安装、扩展 apt 安装、php.ini 双路、FPM pool、重载 | env, template, exec, fs |
| mysql | `internal/mysql` | 3 | 安装、建库建用户改密、导入导出、my.cnf 双路、GTID 复制供 ha 调用 | env, exec, fs, template |
| firewall | `internal/firewall` | 4 | 生成独占规则集、表单、原文、`nft -c`/`nft -f`、确认窗口与回滚、login_ban 集合 | template, exec, fs, settings |
| log | `internal/logview` | 5 | 多来源查看、筛选、跟随、从日志抽统计、接管 logrotate | fs, scheduler, site |
| monitor | `internal/monitor` | 5 | 读 `/proc` 与基础服务状态，写入 SQLite | store, scheduler |
| cron | `internal/cron` | 5 | 用户 crontab 可视化编辑；与 scheduler 分家：一个改系统 crontab，一个跑面板内部任务 | exec, fs |
| migrate | `internal/migrate` | 6 | 配对令牌、握手、临时 SSH 钥、预检、rsync、逻辑导出导入、增量、作废钥 | site, nginx, php, mysql, ssl, firewall, settings, exec |
| ha | `internal/ha` | 7 | 角色与任期、**拉模型**（备机 rsync / 备机连 3306 / 备机拉配置）、404 模式、启用主模式、自我保护、master 时为 nginx/mysql 写 `After=lnmp-panel.service` drop-in | migrate, mysql, nginx, firewall, scheduler |

## 4. 官方插件

| 插件 | 包路径 | build tag | 阶段 | 职责 |
|---|---|---|---|---|
| 文件上传下载 | `plugins/filexfer` | `plugin_filexfer`（发布标签 `plugin_all` 含之） | 8 | 在已鉴权前提下按路径上传/下载。不是文件管理器，不做在线编辑、改权限、整盘浏览树以外的最小选文件 |

发布二进制：`go build -tags plugin_all`。运行时仍可停用（不挂路由、不进菜单）。

## 5. 明确不做（编译单元里不得出现）

| 功能 | 处理 |
|---|---|
| WebSSH / 在线终端 | 核心不做，插件也不做 |
| 完整文件管理器（浏览编辑改权限） | 不做。官方插件只上传下载 |
| 邮件服务器、FTP、Docker 管理、软件商店 | 不做 |
| 多用户、多语言、HTTP 明文、自动 DNS 切换、自动故障接管 | 不做 |
| 定时备份到对象存储 | 后期；迁移稳定后再说。migrate 只预留「清单与打包结构」 |
| inotify 实时文件同步 | 后期；ha 只做自适应 rsync |
| pecl 编译扩展、MariaDB、Apache、非 LTS Ubuntu | 不做 |
| phpMyAdmin 内嵌 | 不做；只做建库建用户导入导出 |

## 6. 模块间关键约定

1. **站点是配置的锚点。** nginx / SSL / 日志路径 / PHP 版本都挂在 `sites` 上，不在各模块各记一份域名。
2. **nginx 是唯一写站点 conf 的模块。** site 保存后调用 nginx 渲染并 reload。ssl 只提供证书路径给 nginx 模板变量。
3. **firewall 是唯一写 nftables 的模块。** auth 的登录封禁（阶段 4 起、且跳过运维白名单 IP）、ha 的主/备白名单都调用 firewall 的集合接口，不直接 `nft`。
4. **ha 不复制 migrate 的传输实现。** 配置拉取、rsync、配对令牌复用 migrate 导出的函数。同步一律由备机发起。
5. **scheduler 不执行领域细节。** 它只按注册的 Job 调用 ssl.RenewDue、log.Aggregate、ha.SyncOnce。每个 Job 独立 goroutine，同一 ID 未结束不重入。
6. **任何模块改系统文件必须经 fs 写前备份**，失败可回看备份目录。
7. **插件不得绕过内部 API 直接改库。** 只拿 `plugin.Context` 里的服务接口。

## 7. 内部调度任务清单（阶段 5 起注册，证书续期在阶段 2 先挂上）

| Job ID | 周期 | 模块 | 说明 |
|---|---|---|---|
| `ssl.renew` | 每天 | ssl | 到期前 30 天续期 |
| `log.aggregate` | 每小时 | log | 从 access.log / auth.log / 慢查询抽统计 |
| `metrics.sample` | 15 秒 | monitor | 采样 `/proc` |
| `metrics.rollup` | 每小时 | monitor | 聚合到小时桶 |
| `ha.filesync` | 自适应 | ha | **仅备机**发起 rsync |
| `session.purge` | 每小时 | auth | 清过期会话 |
| `login_attempts.purge` | 每天 | auth | 删除 30 天以前的登录尝试记录（S6） |

用户 crontab 不走这张表。
