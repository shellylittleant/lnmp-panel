# 15 两台真机迁移与热备测试指南

> 写给需求方本人。对应程序包 `发布/lnmp-panel-amd64.tar.gz`（commit `afea6c6`，含全部官方插件）。
> A 机是已经跑过 docs/13 的那台，B 机是新准备的。测完 B 机可以重装。

## 一、准备

| 项 | 要求 |
|---|---|
| B 机 | x86_64，全新 Ubuntu 24.04，不装 Docker，公网 IP |
| 安全组 | A、B 都放行 22、80、443、20000 到 49151；另外 **A 放行 B 的 IP 访问 3306**，**B 放行 A 的 IP 访问 3306**（热备回切时方向会反过来） |
| 域名 | 测试域名的 A 记录现在指向 A，切换时你手动改 |
| 两台机器都升级到本次程序包 | A 机重跑一次安装脚本即可升级，B 机按 docs/13 第二节全新安装 |

**升级 A 机**（配置和密码不变）：

```bash
scp "~/lnmp-panel/发布/lnmp-panel-amd64.tar.gz" root@A的IP:/root/
ssh root@A的IP 'cd /root && rm -rf lnmp && mkdir lnmp && tar -xzf lnmp-panel-amd64.tar.gz -C lnmp && cd lnmp && bash scripts/install.sh && lnmp-panel version'
```

**安装 B 机**：按 docs/13 第二节，运维白名单填你的公网 IP。B 机不要建站，保持空机。B 机也要在环境安装里装好 Nginx、PHP 8.3、MySQL，版本与 A 一致。

## 二、迁移测试（A 搬到 B）

| # | 操作 | 期望 | 结果 |
|---|---|---|---|
| M1 | B 面板：迁移与热备 → 迁移页签 → "生成令牌"，复制令牌 | 得到一串 `16位.32位` 的令牌，15 分钟内有效 | |
| M2 | A 面板：迁移页签，填 B 的面板地址（完整的 `https://IP:端口/前缀`）和令牌，点"配对" | 显示 B 的证书指纹，配对成功 | |
| M3 | A 面板：点"预检" | 通过；若 B 有站点会提示"目标机已有 N 个站点将被替换" | |
| M4 | A 面板：点"全量同步"，等进度到完成 | 完成；任务详情列出 B 还缺什么（应为空，因为 B 已装齐） | |
| M5 | B 面板：网站页 | 出现 A 的站点，证书也在 | |
| M6 | B 面板：数据库页 | 出现 A 的库和用户 | |
| M7 | B 服务器上用 A 的数据库用户密码登录：`mysql -u用户 -p 库名` | 能登录 | |
| M8 | B 面板：防火墙页 | 出现"迁移带来的待应用规则"，端口是 B 自己的；点应用并确认 | |
| M9 | 把域名 A 记录改指向 B，等生效，浏览器打开 `https://你的域名/` | 站点内容与 A 一致，证书正常 | |
| M10 | A 服务器上给站点目录加一个文件，A 面板点"增量同步" | B 上出现该文件 | |
| M11 | A 面板点"完成迁移" | A 上临时密钥删除，B 上授权段删除（`grep LNMP-PANEL-MIGRATE /root/.ssh/authorized_keys` 无输出） | |
| M12 | 把域名改回指向 A | 站点恢复由 A 服务 | |

## 三、热备测试（A 主 B 备，故障切换，恢复回切）

做之前先在 A 上建一张表，方便看数据是否同步。A 服务器上：

```bash
mysql --defaults-extra-file=/var/lib/lnmp-panel/secrets/mysql-panel.cnf -e "CREATE DATABASE IF NOT EXISTS hatest; CREATE TABLE IF NOT EXISTS hatest.t(id INT PRIMARY KEY, note VARCHAR(50)); INSERT INTO hatest.t VALUES (1,'from-A');"
```

| # | 操作 | 期望 | 结果 |
|---|---|---|---|
| H1 | A 面板：热备页签 → "生成令牌" | 得到令牌 | |
| H2 | B 面板：热备页签，填 A 的面板地址和令牌，点"配对（本机为备）" | B 显示角色 standby，A 显示 master | |
| H3 | B 面板：点"开始同步"，等一两分钟看状态 | 复制正常，落后为秒级，文件同步间隔约 60 秒 | |
| H4 | B 服务器上查数据：`mysql --defaults-extra-file=/var/lib/lnmp-panel/secrets/mysql-panel.cnf -e "select * from hatest.t"` | 看到 from-A | |
| H5 | 浏览器直接访问 B 的公网 IP 或把 hosts 指向 B | 返回 404，备机不对外服务 | |
| H6 | A 上再插一行：`INSERT INTO hatest.t VALUES (2,'before-failover')`，10 秒后在 B 查 | B 看到第 2 行 | |
| H7 | 模拟 A 故障：A 服务器上 `systemctl stop nginx mysql lnmp-panel` | A 站点打不开 | |
| H8 | B 面板：点"启用主模式" | B 角色 master，任期加 1，站点在 B 上 200 | |
| H9 | 把域名改指向 B，浏览器打开 | 站点正常，证书正常 | |
| H10 | B 上插一行：`INSERT INTO hatest.t VALUES (3,'on-B')` | 成功，说明 B 可写 | |
| H11 | 恢复 A：A 服务器上 `systemctl start lnmp-panel`（面板会先启动，再拉起 nginx 和 mysql） | A 面板热备状态显示"对端已是主机，本机已只读并挂维护页"；浏览器访问 A 的 IP 得到 503 维护页 | |
| H12 | A 面板：点"降级为备"，再点"开始同步" | A 角色 standby，复制正常 | |
| H13 | A 上查数据 | 看到第 3 行 on-B | |
| H14 | 回切：A 面板点"启用主模式" | A 角色 master，任期再加 1；B 面板状态显示已只读并挂维护页（不需要重启 B） | |
| H15 | 把域名改回指向 A | 站点正常 | |
| H16 | B 面板：点"降级为备"，"开始同步" | B 角色 standby，复制正常，回到最初状态 | |
| H17 | 两边各执行一次面板数据库连通检查：`mysqladmin --defaults-extra-file=/var/lib/lnmp-panel/secrets/mysql-panel.cnf ping` | 两边都是 alive | |
