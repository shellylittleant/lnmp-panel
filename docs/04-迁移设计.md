# 04 迁移设计

> 记录日期：2026-09-16
> 状态：需求已确认，方案为我的建议，可推翻

## 需求

A 机和 B 机都装了本面板。把 A 机的**全部配置和数据**完整同步到 B 机。仅此而已。

## 同步内容清单

| 类别 | 内容 |
|---|---|
| 站点文件 | 各站点根目录 |
| Nginx | 站点 conf、全局 conf、用户模板 |
| PHP | 已安装版本、各版本扩展列表、php.ini、php-fpm pool 配置 |
| MySQL | 全部数据库、用户与权限、my.cnf |
| SSL | 证书、私钥、ACME 账户信息、续期配置 |
| 防火墙 | 规则集 |
| 面板自身 | 站点元数据、模板库、面板设置、插件及其配置 |

## 方案建议（对应原问题 B2、B3、B4）

- **B2 传输方式：两机直连。** 流程：B 面板生成一次性配对令牌；用户在 A 面板输入 B 的地址和令牌；A 通过 B 的面板 API 完成握手，交换临时 SSH 密钥；文件用 rsync over SSH 传输，数据库用逻辑导出后传输再导入；完成后临时密钥作废。不经第三方存储，不需要用户手动配置 SSH 信任。
- **B3 增量：支持。** rsync 天然增量。推荐流程：先全量同步一次（站点可继续运行），切换前再增量同步一次，把停机窗口压到最小。
- **B4 定时备份：后期做。** 打包逻辑与迁移共用，前期先不做，等迁移稳定后作为低优先级加入。

## 目标机预检

同步前 B 面板必须检查：Ubuntu 版本是否在支持窗口、磁盘空间、端口冲突、PHP/MySQL 版本是否可安装。预检不通过则拒绝开始，避免同步到一半失败。
