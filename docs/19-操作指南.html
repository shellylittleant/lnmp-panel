1. 面板简介与通用约定

1.1 定位与设计原则

LNMP 面板是一个运行在 Ubuntu 服务器上的可视化管理后台，用浏览器管理 Nginx、PHP、MySQL、防火墙、日志、定时任务、站点文件，以及面板之间的迁移与主备热备。一个面板只管理它所在的一台机器。

  • SSH 能做的，面板都能做。面板不做小白保护，面向有基础素养的运维人员。危险动作只做二次确认，不阻止。
  • 表单与原文并存。每个配置文件都可以用表单改，也可以直接改原文。改过原文就进入"原文模式"，表单只读，随时可以恢复为模板渲染。
  • 不设上限，只设下限。Ubuntu 24.04 以上、PHP 8.2 以上、MySQL 8.0 以上。
  • 所有写操作进审计。审计日志不可删除。
  • 装东西集中在一处。Nginx、PHP、MySQL、插件都在"设置 → 环境安装"里装。功能页只管用，不管装。

1.2 支持范围与明确不做的功能

系统Ubuntu 24.04 LTS 及以上 LTS，x86_64（当前程序包）。不支持与 Docker 共存，Docker 会改写防火墙规则。
NginxUbuntu 官方源
PHPOndřej PPA，8.2 及以上多版本共存，每个站点各选一个版本
MySQLx86_64 用 MySQL 官方源 8.4 LTS；arm64 用 Ubuntu 源 mysql-server 8.0
防火墙nftables，面板独占管理，安装时会关闭 ufw
证书Let's Encrypt HTTP-01 自动申请与续期；或手动粘贴证书
不做WebSSH 在线终端、邮件服务、FTP、Docker 管理、软件商店、phpMyAdmin、回收站、全盘搜索、自动故障切换、DNS 联动、通配符证书

1.3 界面布局

登录后界面分三块：

  • 左侧主菜单，固定十项，顺序为：概览、网站、文件、数据库、防火墙、日志、定时任务、迁移与热备、设置、审计。
  • 右上角显示当前登录用户名和 退出 按钮。
  • 备机横幅：当本机是热备的备机时，页面顶部持续显示黄色提示"本机为备机，配置由主机同步"。此时所有写操作都会被拒绝，见第 11 章。

页面上的操作结果以右上角浮动消息提示：绿色为成功，红色为失败并带原因，黄色为警告。

1.4 所有配置页共有的机制

网站、数据库 my.cnf、防火墙、PHP 的 php.ini 与 FPM pool、logrotate 这些配置页都遵循同一套机制，理解一次即可通用。

表单模式与原文模式

  • 表单模式（默认）：填表单，点 保存表单，面板用官方模板渲染出完整配置文件写到磁盘。
  • 原文模式：在"原文"文本框里直接改配置文件内容，点 保存原文。保存后该配置进入原文模式，页面顶部显示蓝色"原文模式"提示，表单变为只读。
  • 恢复为模板渲染：点 恢复为模板渲染（防火墙页叫"恢复官方模板"），面板丢弃原文，重新用表单和模板生成配置，退出原文模式。
原文模式下面板不会再碰这个文件的内容，只负责写入磁盘和重载服务。改错了服务起不来，面板会把错误原样返回。

配置漂移与"确认覆盖磁盘"

如果有人在 SSH 里手工改了面板托管的配置文件，面板打开该页时会发现"磁盘内容与面板上次写入不一致"，顶部显示黄色"配置漂移"警告，并把磁盘上的实际内容显示在原文框里。此时无论保存表单还是保存原文，都必须先勾选 确认覆盖磁盘，否则保存被拒绝。这是为了防止面板悄悄覆盖掉别人的手工修改。

生效时间

保存成功的提示里会写"配置在 1 到 2 秒内生效"。面板保存后异步重载对应服务（nginx reload、php-fpm reload 等），不会阻塞页面。MySQL 的 my.cnf 是例外，保存会重启 MySQL。

二次确认

删除文件、覆盖同名文件、解压覆盖、改权限、防火墙应用都会弹出确认框或进入确认窗口。确认框只有 确认 和 取消 两个按钮。

后台任务进度

安装 Nginx、PHP、MySQL，导入 SQL 这类耗时操作会以后台任务运行，按钮旁边实时显示"任务名：阶段 详情"文字，完成后弹出成功提示并刷新页面数据。任务进行中相关按钮禁用，请不要刷新页面离开。

2. 安装、升级与卸载

2.1 准备工作

项要求
服务器x86_64，全新 Ubuntu 24.04 LTS，root 权限，不要安装 Docker
网络公网 IP。云安全组放行 22、80、443，以及 20000 到 49151 整段（面板端口在安装时随机落在这个范围）
域名要申请证书的域名，A 记录指向这台机器
你的电脑能 ssh 和 scp 到服务器。知道自己电脑的公网出口 IP，安装时作为运维白名单

2.2 安装步骤

第 1 步：上传程序包。在你的电脑上执行，把用户名和 IP 换成实际值：

scp lnmp-panel-amd64.tar.gz 用户@服务器IP:/root/

第 2 步：登录服务器安装。把"你的公网IP"换成你电脑的公网出口 IP。这是运维白名单，只有白名单内的 IP 能打开面板，防止别人试密码，也防止你自己输错密码被锁：

ssh 用户@服务器IP
sudo -i
cd /root && mkdir -p lnmp && tar -xzf lnmp-panel-amd64.tar.gz -C lnmp
cd lnmp && OPS_CIDR=你的公网IP/32 bash scripts/install.sh

安装脚本支持两个环境变量：

变量作用
OPS_CIDR运维白名单，逗号分隔的 IP 或 CIDR。留空则任何 IP 都能访问登录页（不推荐）。
BIND_MODE=localhost面板只监听本机 127.0.0.1，必须通过 SSH 隧道访问。适合安全要求高的场景。

安装脚本会做这些事：关闭 ufw、安装 nftables、把二进制装到 /usr/local/bin/lnmp-panel、生成配置与自签证书、注册 systemd 服务并启动。全程约 1 分钟，不联网下载任何东西。

第 3 步：记下安装信息。脚本末尾打印三行：面板地址、用户名 admin、初始密码。忘了随时可以再看：

cat /etc/lnmp-panel/install.info

面板地址形如 https://服务器IP:随机端口/随机路径前缀/。随机端口和随机路径前缀都是安全设计的一部分，直接访问 https://服务器IP:端口/ 而不带路径前缀会得到 404。

第 4 步：浏览器打开面板地址。证书是自签的，浏览器会警告，选择"继续访问"或"高级 → 继续前往"。看到登录页即部署成功。

2.3 首次登录后必须做的事

  1. 用 admin 和初始密码登录。
  2. 到 设置 → 面板 → 修改密码，换掉初始密码。要求 12 位以上，包含大小写字母、数字和符号。
  3. 到 设置 → 面板 → TOTP 二次验证，生成密钥、手机验证器扫码、输入验证码启用。
  4. 到 设置 → 环境安装，按需安装 Nginx、PHP、MySQL。
  5. 到 防火墙，检查默认规则中的 SSH 端口是否正确，然后应用并确认一次，让完整规则集写入开机配置。

2.4 升级与卸载

升级：把新程序包解压后重新运行安装脚本即可。脚本检测到已有配置会提示"检测到已有配置，跳过初始化，仅更新二进制与服务"，面板地址、密码、所有数据都保留：

cd /root && rm -rf lnmp && mkdir lnmp && tar -xzf lnmp-panel-amd64.tar.gz -C lnmp
cd lnmp && bash scripts/install.sh && lnmp-panel version

卸载：

cd /root/lnmp && bash scripts/uninstall.sh

卸载只删面板本身，不删站点文件、不删 MySQL 数据、不卸载 Nginx/PHP/MySQL。

2.5 命令行工具

面板二进制同时是命令行工具，在服务器上以 root 执行：

命令作用
lnmp-panel version显示版本号与 commit
lnmp-panel whitelist show显示当前运维白名单
lnmp-panel whitelist clear清空白名单，任何 IP 可访问。出口 IP 变化把自己挡在外面时用这条恢复
lnmp-panel whitelist set 1.2.3.4/32,10.0.0.0/8重设白名单
systemctl restart lnmp-panel重启面板服务
journalctl -u lnmp-panel -n 100看面板自身日志

白名单命令改的是数据库，立即生效，不需要重启面板。本机回环地址 127.0.0.1 与 ::1 永远不受白名单限制，所以 SSH 隧道总是可以进面板。

3. 登录与安全策略

登录页只有用户名、密码两个框和 登录 按钮。用户名固定为 admin。

  1. 输入密码点登录。密码正确且未开 TOTP，直接进入概览。
  2. 已开 TOTP 时，页面提示"请输入 TOTP 验证码"，出现第三个输入框。打开手机验证器输入 6 位数字，再点登录。验证码步骤必须在 5 分钟内完成，且必须从同一个 IP 发起。
失败锁定同一 IP 在 15 分钟内密码错 5 次，该 IP 锁定 30 分钟，期间提示"已锁定"。锁的是来源 IP，不是账号。运维白名单外的 IP 根本到不了登录页。
会话时长2 小时无操作自动过期；有操作则滑动延长，但从登录起最长 12 小时，之后必须重新登录。
修改密码修改成功后其他所有会话立即踢出。
退出点右上角 退出，当前会话立即作废。
路径前缀不带随机路径前缀的任何请求都返回 404，扫描器看不到登录页。

4. 概览

登录后的首页，每 5 秒自动刷新，分四块。

区块内容与操作
手动证书到期提醒只在有手动填入的证书 30 天内到期时出现，黄色横幅列出域名与到期日。手动证书不自动续期，需到站点详情重新粘贴新证书，或改回自动申请。
系统概览主机名、系统版本、面板监听地址、路径前缀、进程 PID、运行秒数，以及 Nginx / PHP / MySQL 三个服务的运行状态（running、stopped 等）。
环境状态Nginx 是否已装、已装的 PHP 版本列表、MySQL 是否已装及版本。下方 去环境安装 按钮直达设置页的环境安装页签。
资源指标采样时间与 1 分钟负载、CPU 百分比进度条、内存已用/总量进度条、磁盘已用/总量进度条、网络累计收发字节数，以及最近 1 小时 CPU 折线。调度器每 15 秒采样一次写入本地库，原始数据保留 7 天，按小时聚合保留 90 天。

刚安装完的前 15 秒资源指标会显示"尚无采样"，属正常。

5. 网站

网站页有两个页签：站点 与 模板库。

5.1 站点列表与新建站点

若尚未安装 Nginx，页面顶部显示黄色"尚未安装 Nginx"提示和 去环境安装 按钮，此时建站会失败，请先装 Nginx。

新建站点卡片有三个输入框：

字段说明
标识站点的唯一英文 key，例如 blog。用于目录名 /var/www/blog、配置文件名 /etc/nginx/sites-available/blog.conf、日志过滤等。创建后不可改。
名称给自己看的备注名，可中文。
域名一个或多个域名，逗号分隔，例如 example.com, www.example.com。

点 创建。面板会建根目录 /var/www/标识、写入一个"站点已创建"的欢迎页 index.html、用官方模板生成 nginx 配置并重载。此时浏览器打开 http://域名/ 应能看到欢迎页。

站点列表显示标识、名称、域名、是否启用、是否漂移。点击任意一行进入站点详情。

5.2 站点详情表单

字段说明
名称备注名
域名逗号分隔，改完保存即生效
根目录站点文件所在目录。旁边 打开目录 按钮直接跳到文件页的这个目录。
PHP 版本下拉选择。"静态（无 PHP）"表示纯静态站；其余为已安装的 PHP 版本。选了版本，nginx 配置会把 .php 交给对应版本的 php-fpm。
反代目标填 http://127.0.0.1:3000 这类地址，则站点变为反向代理，所有请求转发过去。留空为普通站点。
HTTP/2勾选后 HTTPS 使用 HTTP/2，默认开。
站点模板选择用哪个 nginx_site 类型的模板渲染此站点，默认官方模板。可选用户自定义模板，见 5.7。
伪静态选择一个 nginx_rewrite 类型的模板作为伪静态规则片段（如 WordPress、ThinkPHP 等），留空为无。
确认覆盖磁盘出现"配置漂移"警告时必须勾选才能保存。

四个按钮：

  • 保存表单：按表单和模板重新渲染配置并重载 nginx。
  • 申请/签发证书：见 5.3。
  • 恢复为模板渲染：退出原文模式。
  • 删除站点：见 5.6。

5.3 自动申请证书

点 申请/签发证书，面板通过 Let's Encrypt 的 HTTP-01 方式签发证书，成功后自动写入站点配置、开启 HTTPS 并把 HTTP 自动跳转到 HTTPS。整个过程约 10 到 30 秒。

前提条件：

  • 站点的每个域名都已解析到本机公网 IP；
  • 80 端口对公网开放（安全组与防火墙都放行）；
  • 域名不能是通配符（*.example.com），HTTP-01 不支持。

自动证书到期前 30 天由内部调度器自动续期，无需人工干预。续期失败会写入面板日志。

5.4 手动填入证书

站点详情下方"手动填入证书"卡片，用于已有商业证书或在别处申请的证书。

  1. 把证书链 PEM（服务器证书加中间证书，以 -----BEGIN CERTIFICATE----- 开头，可能有多段）粘贴到第一个框。
  2. 把私钥 PEM 粘贴到第二个框。
  3. 点 保存手动证书。

面板校验规则：证书必须能解析；私钥必须与证书匹配；已过期的证书拒绝；证书域名不覆盖站点域名时只警告不阻止（黄色提示）。保存后写到与自动证书相同的位置并重载 nginx。

手动证书不参与自动续期。到期前 30 天概览页和站点页会提醒。到期后需重新粘贴新证书，或点"申请/签发证书"改回自动申请。

5.5 nginx 配置原文

最下方"nginx conf 原文"卡片显示该站点完整的 nginx 配置文件。可以直接编辑后点 保存原文，之后站点进入原文模式，表单只读。要回到表单，点 恢复为模板渲染，注意这会丢弃原文里的手工修改。

典型用法：需要加一段模板没提供的 location 时，先用表单配好基础项，再切原文加内容。

5.6 删除站点

点 删除站点 后立即删除，无二次确认。删除的是站点记录、nginx 配置和证书记录，根目录下的文件与数据库都保留，需要时到文件页和数据库页自行清理。

5.7 模板库

网站页第二个页签。列出所有模板，分三列：类型、名称、来源。类型包括 nginx_site（站点配置）、nginx_rewrite（伪静态）以及 php.ini、pool、my.cnf、nftables 等各类配置模板。来源分官方与用户。

  • 点击一行，下方显示模板内容。官方模板只读，看得到改不了。
  • 用户模板可以改名称和内容，点 保存。

模板用 Go 模板语法，变量由面板填入。修改用户模板后，使用该模板的站点要重新保存一次表单才会重新渲染。

6. 文件

全目录文件管理器，默认打开 /var/www，可以进入任何目录。面向建站运维，不做全盘搜索和回收站。

6.1 界面元素与浏览

元素说明
站点快捷跳转下拉列出所有站点及其根目录，选中即跳转。
路径框 + 打开直接输入绝对路径回车或点打开。
当前目录过滤按文件名关键字过滤当前目录的列表，回车生效。只过滤当前目录，不递归。
面包屑路径框下方一行 / var www blog，点任意一级返回上级。
列表名称、大小、权限、属主、属组、修改时间。双击目录进入。每行左侧有复选框，操作按钮作用于勾选的项。

6.2 上传、新建、下载

上传到目录

点 上传到目录 选择一个或多个文件，选完立即上传到当前目录。单文件上限 2 GB，流式写入，不占内存。目标已有同名文件时弹出"目标已存在，确认覆盖？"。上传完成后文件属主自动改为 www-data，权限 644。

新建目录 / 新建文件

在"新目录或文件名"框输入名字，点 新建目录 或 新建文件，在当前目录创建。新建文件不填名字时默认为 untitled.txt。

下载

勾选一项点 下载。文件直接下载；目录打包为 zip 流式下载，不限大小。若目录下含面板自身的密钥或数据库文件，整个请求被拒绝并提示"该目录包含面板密钥或数据库，请缩小范围"。

6.3 删除、复制、移动

删除

勾选一项或多项点 删除，弹出"确认删除选中的 N 项？不可恢复"，确认后删除。目录会递归删除。

复制 / 移动

  1. 勾选一项（文件或目录）。
  2. 在"复制/移动目标路径"框填目标的完整路径。填目录路径则放进该目录，填带新文件名的路径则同时改名。
  3. 点 复制 或 移动。目标已存在则弹出覆盖确认。

重命名就是移动到同目录下的新名字。禁止把目录复制或移动到它自己的子目录里。

6.4 解压与压缩

解压：勾选一个 zip 或 tar.gz 文件点 解压，弹出"解压可能覆盖同名文件，确认？"，确认后解压到当前目录。解压出的文件属主改为 www-data，目录 755、文件 644。压缩包里的软链接和硬链接条目会被跳过。这是部署站点最常用的动作：上传站点压缩包到根目录，解压，完成。

压缩 zip：勾选一项或多项点 压缩 zip，在当前目录生成 archive.zip。已有同名 archive.zip 会被覆盖，压缩完可用移动功能改名。

6.5 在线编辑

勾选一个文件点 编辑，弹出全屏编辑器（CodeMirror，按扩展名对 PHP、HTML、CSS、JS、JSON 做语法高亮和行号）。改完点 保存 直接覆盖磁盘文件，点 关闭 放弃。

限制：只能编辑 1 MB 以内的文本文件，超过会提示"超过 1 MB，请下载后编辑"。

6.7 受保护的面板文件

以下路径可以看到但不能通过面板操作，列表中名字前带 🔒 锁图标，复选框禁用，点击提示"面板自身文件，请走 SSH"：

8. 防火墙

面板独占管理 nftables，安装时已关闭 ufw。核心保障：官方模板始终放行 SSH 端口和面板端口，且任何规则应用后都有 60 秒确认窗口，把自己锁在外面会自动回滚。

8.1 表单字段

字段说明
SSH 端口安装时自动探测填入。改 sshd 端口后务必同步改这里。
面板端口自动填入，一般不改。
入站策略drop：默认拒绝，只放行列出的端口（推荐）。accept：默认放行，防火墙形同虚设。
公网 80/443勾选放行 HTTP 与 HTTPS。建站必勾。
额外 TCP 端口逗号分隔，如 3306, 8080。
额外放行 CIDR逗号分隔，这些网段访问任何端口都放行，如内网 10.0.0.0/8。

8.2 操作流程（务必按顺序）

  1. 改表单，点 保存表单。提示"已保存（尚未应用到内核）"。这一步只写文件，规则还没生效。
  2. 点 应用（进入确认窗口）。规则加载到内核，页面顶部出现黄色横幅和倒计时"还剩 N 秒确认，否则自动回滚"。
  3. 倒计时内验证：另开一个终端 ssh 登录服务器，确认能连；刷新面板确认能开。
  4. 验证没问题，点横幅里的 确认保留。规则写入开机配置，倒计时消失。
  5. 有问题，点 立即回滚，或什么都不做等 60 秒。

自动回滚触发条件：60 秒内没点确认；或面板心跳中断（比如面板端口被新规则挡住）；或确认前面板进程重启。回滚后恢复到上一次确认过的规则。

保存不等于应用。只点了保存表单没点应用，规则不会生效，重启后也不会生效。

8.3 规则集原文

下方"规则集原文"是完整的 nftables 规则文件，可直接编辑后点 保存原文，然后同样要走应用与确认。恢复官方模板 丢弃原文，按表单重新生成。

面板自身的登录防护：运维白名单以外的 IP 无法访问面板端口，这条不在 nftables 里，而是面板进程内判断，本机回环永远放行。

8.4 迁移带来的待应用规则

通过迁移功能把配置同步到本机后，防火墙页顶部会出现蓝色提示"迁移带来的待应用规则：已按本机 SSH 与面板端口重写，尚未写入开机规则"。核对表单无误后点应用，走正常确认流程。

11. 迁移与热备

一个页面两个页签。迁移是一次性把 A 机的全部内容搬到 B 机；热备是 B 机持续追随 A 机，A 故障时人工切换到 B。两者都要求两台机器各自装好面板，并且都装好 Nginx、PHP（版本一致）、MySQL。

11.1 迁移：把 A 机整体搬到 B 机

同步内容：站点文件、nginx 站点配置与用户模板、PHP 各版本的 php.ini 与 pool、MySQL 全部库与用户权限与 my.cnf、SSL 证书与私钥与 ACME 账户、防火墙规则、面板的站点元数据与设置。B 机上已有的同名站点会被替换。

传输方式：两机直连。A 通过 B 的面板 API 握手并交换临时 SSH 密钥，文件走 rsync over SSH，数据库逻辑导出后传输再导入。完成后临时密钥作废，不经第三方存储。

操作步骤

步在哪台操作
1B迁移页签 →"本机作为目标（B）"卡片 → 点 生成令牌。得到一串令牌和过期时间，15 分钟内有效。复制令牌。
2A"本机作为源（A）"卡片 → 目标地址填 B 的完整面板地址 https://IP:端口/路径前缀，令牌框粘贴令牌 → 点 配对。成功提示"配对成功"，配对关系 7 天无操作自动过期。
3A点 预检。检查 B 的系统版本、磁盘空间、PHP 与 MySQL 是否就绪。若 B 已有站点，会列出"目标机已有 N 个站点将被替换"，必须勾选 确认替换目标机已有站点 才能继续。红色错误必须先解决。
4A点 全量同步。下方"进度"卡片每 2 秒刷新阶段、详情、百分比。站点在 A 上可继续运行。完成后详情列出 B 缺什么（如 PHP 版本），按站点实际使用版本汇总。
5B检查网站页、数据库页是否都出现了 A 的内容。防火墙页会出现"迁移带来的待应用规则"，核对后应用并确认。
6DNS把域名解析改指向 B。
7A切换前再点一次 增量同步，把 DNS 传播期间 A 上的新变化补到 B。可以多次点。
8A点 完成迁移。A 上的临时密钥删除，B 上的授权段删除。

取消并作废钥 与完成迁移动作相同，用于中途放弃。放弃后 B 上已同步的内容保留，需要时手工清理。

迁移不会改 B 机自己的面板密码、面板端口、运维白名单和 SSH 端口。防火墙规则会按 B 机的实际端口重写后等待人工应用。

11.2 热备：主备建立、故障切换与回切

概念

  • 主机对外服务并接受写入；备机只接收同步，80/443 对任何请求一律返回 404，MySQL 只读，面板所有写操作拒绝并显示顶部黄色横幅。
  • 拉模型：文件由备机定时 rsync 拉取（默认 60 秒，一轮没跑完自动拉长间隔），MySQL 用原生 GTID 主从复制持续同步，配置由备机定时拉取。
  • 任期：每次有人点"启用主模式"，任期加 1。两台机器比较任期，大的为主。
  • 自我保护：旧主机重新启动时会先问对端"你是主吗"，对端任期更大就把自己置为只读并挂 503 维护页，等运维处理。
  • 第一版全部人工：不做自动故障检测，不自动接管，不改 DNS。面板只提供按钮和状态。配对长期有效。
  • 两台机器的面板管理员密码在配对后共用，随同步传播。

网络要求

安全组与防火墙：A 放行 B 的 IP 访问 SSH、3306、面板端口；B 放行 A 的 IP 访问 3306 和面板端口。回切时方向反过来，所以两边都互相放行最省事。热备状态卡片的"防火墙"行会提示缺哪条。

建立热备（A 主 B 备）

步在哪台操作
1A热备页签 →"本机作为主机"→ 点 生成热备令牌，复制令牌。握手需在过期时间前完成，握手成功后配对长期有效。
2B"本机作为备机"→ 主机地址填 A 的完整面板地址，粘贴令牌 → 点 配对（本机为备）。B 显示角色"备机"，A 显示"主机"。
3B点 开始同步。首次会全量拷贝文件并建立 MySQL 复制，几分钟后状态卡片显示"MySQL 复制 正常"、落后秒数为个位数。

故障切换（A 挂了）

步在哪台操作
1B热备页签 → 点 启用主模式。B 停止拉取、MySQL 切可写、nginx 启用全部站点，角色变主机，任期加 1。
2DNS把域名解析改指向 B。

A 恢复后回切到 A

步在哪台操作
1AA 启动后自我保护生效，状态显示"对端已是主机，本机已只读并挂维护页"，访问 A 得到 503。
2A点 降级为备，再点 开始同步。A 从 B 拉取这段时间的数据，等"MySQL 复制 正常"且落后接近 0。
3A选低峰时段点 启用主模式。A 变主机，任期再加 1；B 收到通知自动只读并挂维护页。
4DNS把域名改回指向 A。
5B点 降级为备，再点 开始同步。回到最初的 A 主 B 备。

也可以不回切，让 B 长期当主，A 当备。角色是对称的。

字段含义

自我保护红字出现表示本机已只读并挂维护页，需要人工点"降级为备"。

12.1 面板页签

TOTP 二次验证

  1. 点 生成绑定密钥，页面显示二维码和 otpauth 链接。
  2. 用 Google Authenticator、Microsoft Authenticator、1Password 等扫描二维码，或手工录入链接里的密钥。
  3. 在"验证码"框输入验证器当前显示的 6 位数字，点 启用。状态变为"已开启"。
  4. 关闭：在"登录密码"框输入当前密码，点 关闭 TOTP。
手机丢失又没备份密钥时，本版本没有绕过 TOTP 的自助手段，需联系开发者处理。启用前请把 otpauth 链接或密钥抄下来妥善保存。

12.2 环境安装页签

Nginx

PHP

操作方法
添加 PHP 源点 添加 PHP 源（Ondřej PPA）。首次必须做，之后版本下拉才会出现 8.2 到最新版。
安装版本版本下拉选一个标"可装"的版本，点 安装此版本 FPM/CLI。约 1 到 2 分钟。多个版本可并存。
扩展选中已装版本后出现"扩展"卡片。已装扩展以标签显示，点标签上的 × 卸载。下拉选或手输扩展名（mysql、gd、curl、mbstring、xml、zip、bcmath、intl、redis、imagick、opcache 等），点 安装扩展（apt）。
php.ini 片段表单项：upload_max_filesize、post_max_size、memory_limit、max_execution_time、display_errors、opcache.enable、opcache.memory_consumption、opcache.max_accelerated_files、opcache.validate_timestamps。保存表单 后自动 reload 该版本的 php-fpm。也可改原文。面板只写自己的片段文件，不改主 php.ini。
FPM pool表单项：user、pm、pm.max_children。listen 固定不能在表单改，要改用原文。保存后 reload。
确认覆盖磁盘最下方单独一个复选框，php.ini 与 pool 共用，漂移时必勾。

MySQL

显示计划来源与状态。x86_64 机器用 MySQL 官方 apt 源 8.4 LTS，arm64 用 Ubuntu 源 8.0，面板按架构自动选择。点 安装 MySQL，约 3 到 5 分钟。安装完成后面板自动创建管理账号 lnmp_panel@localhost，凭据在 /var/lib/lnmp-panel/secrets/mysql-panel.cnf，权限 0600。MySQL root 账号保持系统默认的 auth_socket 方式，SSH 上 mysql 直接可登。

14. 常见问题与排错

现象原因与处理
打开面板地址显示 404路径前缀漏了或错了。看 cat /etc/lnmp-panel/install.info 里的完整地址。
面板打不开，浏览器一直转圈或拒绝连接多半是当前网络的出口 IP 不在运维白名单。SSH 上去执行 lnmp-panel whitelist clear 或 whitelist set 新IP/32。也检查安全组是否放行了面板端口。
提示"已锁定"同 IP 15 分钟内错 5 次密码，锁 30 分钟。等待或换 IP。
忘记面板密码初始密码在 /etc/lnmp-panel/install.info。改过之后又忘了，本版本没有自助重置命令，请联系开发者处理。内测期间请把密码存进密码管理器。
浏览器证书警告面板用自签证书，正常现象，选择继续访问。
应用防火墙后 SSH 连不上不要慌，60 秒内自动回滚。回滚后检查 SSH 端口填得对不对。
防火墙确认过了，重启后规则没了确认是否真的点了"确认保留"。只保存没应用、或应用没确认，都不会写入开机规则。
页面顶部一直有"配置漂移"有人 SSH 手改了文件。想保留手改内容就什么都不做；想让面板接管就勾"确认覆盖磁盘"后保存。
表单是灰的改不了处于原文模式。点"恢复为模板渲染"，注意会丢弃原文修改。
申请证书失败逐项检查：域名是否解析到本机；80 端口安全组和防火墙是否放行；是否通配符域名；Let's Encrypt 对同一域名一周有签发次数限制。
建站后域名打开是 nginx 默认页或别的站域名没填对或 DNS 未生效。站点详情核对域名，SSH 上 nginx -T | grep server_name。
PHP 站点显示源码或 502站点详情 PHP 版本选了"静态"，或所选版本的 php-fpm 没起来。环境安装页确认已装，SSH 上 systemctl status php8.3-fpm。
文件页某些文件带锁点不了面板自身的数据库和密钥，设计如此，需要动就走 SSH。
编辑提示"超过 1 MB"在线编辑只支持 1 MB 内文本。下载后本地改再上传覆盖。
页面顶部黄色"本机为备机"，所有保存都失败本机是热备备机，只接收同步。要在主机上改；或到热备页签"启用主模式"。
热备状态"MySQL 复制 未就绪"多为 3306 没互相放行。看状态卡片"防火墙"和"告警"行，检查两边安全组。
访问站点得到 503 维护页本机触发了自我保护，对端已是主机。到热备页签点"降级为备"再"开始同步"。
导入 SQL 一直不动大库耗时长，按钮旁有阶段提示。不要刷新页面。可到定时任务页看内部调度器有无错误。
改了 my.cnf 后 MySQL 起不来参数值非法（如 buffer pool 超过物理内存）。原文框改回去保存，或 SSH 改 /etc/mysql/mysql.conf.d/lnmp-panel.cnf 后 systemctl restart mysql。
面板自己挂了systemd 会在 2 秒内自动拉起，1 分钟内连续失败 5 次才会放弃。仍不行看 journalctl -u lnmp-panel -n 100。
