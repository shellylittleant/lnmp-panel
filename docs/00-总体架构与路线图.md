# 00 总体架构与路线图

> 对应 `docs/11-协作流程.md` 阶段 0：总体架构与开发路线图。
> 约束来源：项目根 `docs/00`～`docs/11`。本文件是执行落点，不修改需求文档。

## 1. 产品与交付形态

面向 Ubuntu LTS 的单机 LNMP 运维面板。一个面板管一台机器。交付物是 **一个 Go 静态二进制**：前端构建产物用 `embed` 打进去，`systemd` 一个服务跑起来。无运行时语言依赖，无外部数据库，无 Docker。

| 项 | 值 |
|---|---|
| 产品内部名 | LNMP 面板 |
| 二进制名 | `lnmp-panel` |
| systemd 单元 | `lnmp-panel.service` |
| Go module 路径 | `lnmp-panel`（公开发布前不绑远程仓库地址） |
| 界面语言 | 只中文 |
| 许可证 | 首次公开发布前再定，本仓库阶段内不放 LICENSE |

## 2. 硬约束（启动即检查，不满足则拒绝运行）

## 3. 分层架构

```
┌──────────────────────────────────────────────────────────┐
│  Vue 3 + TypeScript SPA（embed 进二进制）                  │
│  无业务逻辑：只调 HTTPS API，只渲染中文界面                  │
└────────────────────────────┬─────────────────────────────┘
                             │ HTTPS，随机高位端口，随机路径前缀
                             │ 无前缀的请求一律 404
┌────────────────────────────▼─────────────────────────────┐
│  HTTP 适配层  internal/http                                │
│  路由、TLS、会话、CSRF、登录锁定、审计切面、错误信封         │
└────────────────────────────┬─────────────────────────────┘
                             │ 只调用内部服务接口
┌────────────────────────────▼─────────────────────────────┐
│  内部 API（Go 接口）  所有功能的唯一入口                    │
│  界面走 HTTP → 内部 API；未来主控面板只代理同一套 HTTP      │
│  热备按钮、迁移、插件也只走这套接口                         │
└────────────────────────────┬─────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────┐
│  领域模块（官方核心，始终编译；自身也按插件接口注册钩子）     │
│  site nginx ssl php mysql firewall log monitor            │
│  cron migrate ha template settings env                    │
└────────────────────────────┬─────────────────────────────┘
                             │
┌──────────────┬─────────────┴──────────────┬──────────────┐
│ store        │ exec（命令白名单）          │ plugin 注册表 │
│ SQLite       │ fs + 写前备份               │ 调度器        │
└──────────────┴────────────────────────────┴──────────────┘
```

原则：

1. **界面不进领域。** Vue 不拼 nginx conf，不调 `nft`，不读 `/proc`。
2. **HTTP 不进领域。** handler 只做鉴权上下文、参数校验、调用 service、写审计。
3. **内部 API 稳定于 HTTP 之上。** 阶段 1 就把「功能必须经 service 包」定死，避免后期主控接入时改功能代码（docs/07 多机预留）。
4. **核心模块按插件接口挂钩子。** 阶段 8 冻结接口；此前允许按实现反馈微调，变更写入对应阶段报告。

## 4. 安全落地（对应 docs/07，一条不漏）

| 要求 | 落点 |
|---|---|
| 以 root 运行 | systemd `User=root`。对外接口默认拒绝，中间件放行已认证请求。登录与健康检查除外 |
| 只 HTTPS，无 HTTP 明文模式 | 监听层只挂 TLS 1.2+。不提供关闭 TLS 的配置项。首次启动自签证书，可替换为站点证书 |
| 随机高位端口 | 安装时在 `[20000, 49151]` 生成，写入引导配置。无固定默认端口 |
| 随机登录路径 | 安装时生成 16 字节 hex 前缀。`/` 与无此前缀的路径返回 404，不泄露面板存在 |
| 单管理员 + 强密码 + TOTP | 一个管理员账号。密码：≥12 位且含大小写、数字、符号。TOTP 可选，安装结束提示建议开启 |
| 登录失败锁定与封禁来源 IP | 15 分钟内失败 5 次锁定该 IP 30 分钟。**阶段 1** 只写 `ip_locks` 在应用层拒绝。**阶段 4** firewall 落地后，auth 再调用集合接口写入 nftables `login_ban`。**`ops_ip_cidrs` 白名单内的 IP 只做应用层锁定，永不写入 nftables 封禁**，避免运维连错五次把自己封在面板外 |
| IP 白名单 / 仅本机 | 设置项：`bind_mode=public\|localhost`；`ops_ip_cidrs` 非空时面板端口只放行这些网段 |
| 会话短有效期、绑定 IP、可踢出 | 服务端会话，默认 2 小时，绑定登录 IP，Cookie `Secure; HttpOnly; SameSite=Strict` |
| 写操作审计且面板不可删 | `audit_logs` 无 DELETE/TRUNCATE API。界面只有查询 |
| 防火墙自我保护 | 官方防火墙模板必含 SSH 与面板端口放行。应用规则前进入确认窗口，超时自动回滚 |

补充（安全第一，文档未写细的实现选择）：

- 会话令牌只放 Cookie，不放 localStorage。
- SPA 与 API 同源。写接口校验 CSRF（Cookie 会话 + 响应头下发的一次性头）。
- `internal/exec` 只跑命令白名单，禁止 `sh -c` 拼接用户输入。
- 密钥文件目录权限 `0700`，文件 `0600`。
- 审计日志与登录失败记录不进可被用户清空的「日志查看」删除能力。

## 5. 目标机路径约定

全部写死 Ubuntu 24.04+ 路径，不做探测分支。

### 5.1 面板自身

| 用途 | 路径 |
|---|---|
| 二进制 | `/usr/local/bin/lnmp-panel` |
| 引导配置 | `/etc/lnmp-panel/panel.json`（端口、路径前缀、TLS、库路径、bind） |
| 数据目录 | `/var/lib/lnmp-panel/` |
| SQLite | `/var/lib/lnmp-panel/panel.db` |
| 自签/面板证书 | `/var/lib/lnmp-panel/tls/` |
| 密钥（TOTP、ACME 账户、临时 SSH） | `/var/lib/lnmp-panel/secrets/` |
| 写前备份 | `/var/lib/lnmp-panel/backups/<模块>/<时间戳>/` |
| 面板日志 | `/var/log/lnmp-panel/panel.log` |
| systemd | `/etc/systemd/system/lnmp-panel.service` |
| 安装信息（root 可读） | `/etc/lnmp-panel/install.info`（URL、初始密码提示，权限 0600） |

### 5.2 LNMP 与站点

| 用途 | 路径 |
|---|---|
| 站点根（默认） | `/var/www/<site_key>/` |
| Nginx 站点 conf | `/etc/nginx/sites-available/<site_key>.conf`，软链到 `sites-enabled/` |
| Nginx 全局片段（面板写） | `/etc/nginx/conf.d/lnmp-panel.conf` |
| 站点 access/error 日志 | `/var/log/nginx/<site_key>.access.log`、`<site_key>.error.log` |
| PHP | `/etc/php/<主.次>/fpm/php.ini`（发行版原文件不整份替换）+ 面板片段 `conf.d/99-lnmp-panel.ini`、`pool.d/lnmp-panel.conf`（**版本级**一个 pool，见下） |
| PHP-FPM socket | `/run/php/php<主.次>-fpm.sock`（每版本一个，全站共用） |
| MySQL 配置 | `/etc/mysql/mysql.conf.d/lnmp-panel.cnf`（面板托管片段）+ 官方默认文件原文编辑入口 |
| nftables 规则集（面板独占） | `/etc/lnmp-panel/nftables.conf`，用 `nft -f` 原子加载。`/etc/nftables.conf` 仅一行 `include "/etc/lnmp-panel/nftables.conf"`，并 `enable nftables.service`，保证开机在面板启动前恢复规则。运行时集合（如 `login_ban`）重启即清空，可接受 |
| logrotate（面板托管） | `/etc/logrotate.d/lnmp-panel` |

站点标识 `site_key`：`[a-z0-9][a-z0-9-]{0,62}`，同时是目录名与 conf 文件名。

站点目录权限（阶段 2 起执行，S3）：`/var/www/<site_key>` 属主 `www-data:www-data`，目录 `755`、文件 `644`。filexfer 上传后必须 `chown` 为 `www-data`。

PHP-FPM **第一版按版本级 pool**：每个已装 PHP 版本一个 pool、一个 socket、统一 `www-data`，该版本下所有站点共用。站点级隔离以后再做。

## 8. 核心流程（跨模块，供后续阶段对照）

### 8.1 安装

1. 检查 root、Ubuntu LTS ≥ 24.04。检测到 Docker（`docker.sock` 或 `docker.service` 在跑）则 **拒绝安装**，错误信息明确要求先卸载 Docker 再重试。
2. 安装二进制、目录、随机端口、随机路径、自签证书、随机管理员密码。
3. 写 `/etc/nftables.conf` 为 `include "/etc/lnmp-panel/nftables.conf"`（此时规则集可以是「放行 SSH + 面板端口」的最小集），`systemctl enable nftables.service`。
4. 写 systemd、`enable --now`。
5. 打印面板 URL 与初始密码。运维 IP 白名单：主机角色允许留空；安装时建议填写。切换为备机角色时强制非空且必须包含主机 IP。

### 8.2 写配置的统一步骤（nginx / php.ini / nft / my.cnf / logrotate）

1. 读盘，做漂移检测。
2. 表单或原文 → 渲染或直接采用原文。
3. 若与已有模板内容不同，自动落一条用户模板。
4. 写前备份。
5. 校验（`nginx -t`、`nft -c -f`、`php-fpm -t` 等）。
6. 应用（reload / `nft -f`）。
7. 防火墙额外：确认窗口 + 超时回滚。
8. 记 `last_written_hash`，写审计。

### 8.3 迁移（docs/04）

B 生成一次性配对令牌 → A 输入 B 的地址和令牌 → A 先按令牌里的指纹校验 B 的面板 TLS 证书，通过后才把令牌发往 B → 握手并交换临时 SSH 密钥 → B 预检（Ubuntu 窗口、磁盘、端口、PHP/MySQL 可安装）→ rsync over SSH 传文件，逻辑导出传库 → 切换前再增量一次 → 作废临时密钥。定时备份后期做，本架构只保证打包清单与迁移共用结构，不实现定时备份任务。

配对令牌明文格式：`<B面板证书SHA-256指纹的十六进制前16位>.<随机串>`。A 连接时把证书指纹前 16 位与令牌首段比对，不一致则中止。握手成功后把完整指纹写入 `peers.fingerprint` 并长期固定，之后每次连接都校验。

### 8.4 热备（docs/10，第一版全人工）

角色：`standalone` / `master` / `standby`。任一时刻只有一台主机可写。**统一拉模型**（审核 M1）：备机主动拉，主机不推。

- 文件：备机发起 rsync（配对时备机拿到访问主机的临时 SSH 钥）。自适应间隔（目标 1 分钟，不重叠，超时拉长，超过 5 分钟面板内告警）。inotify 后期。
- MySQL：备机作为 replica 连接主机 3306，GTID 复制；首次用 clone 插件。协议上只能拉，不能由主机推。
- 配置：备机定时拉取，复用迁移的配置同步。
- 备机 nginx：唯一兜底 server，任何域名任何路径 404。同步来的站点 conf 只放 `sites-available`，`sites-enabled` 只留 `nginx_catchall_404`；提升为主时再批量建软链（S5）。
- 备机证书：不申请，从主机拉取。
- 防火墙：
  - **主机**：白名单放行备机 IP 访问 SSH、3306、面板 API；80/443 对公网；运维 IP 访问 SSH 与面板。
  - **备机**：只放行主机 IP 访问面板 API（自我保护查询角色）和运维 IP 访问面板端口；80/443 对公网只回 404。SSH 对运维 IP 放行，避免无法登入抢救（自我保护延续）。
- 「启用主模式」「降级为备」「开始同步」「同步状态」「健康状态」全部是内部 API，第一版只挂按钮，不做自动判定、不接 DNS。
- 自我保护：B 提升为主时写带版本号的任期。A 启动若本地说「我曾是主且备机是 B」，先问 B；B 说自己是主，则 A 把 MySQL 只读、站点改维护页。联系不上 B 则按原状态启动。
- 启动顺序（M8）：进入 `master` 角色时，为 `nginx.service` 与 `mysql.service` 写 drop-in `/etc/systemd/system/<svc>.service.d/lnmp-panel.conf`，内容 `After=lnmp-panel.service`，保证自我保护先于这两个服务启动。退出 HA 时删除 drop-in。联系不上对端时照常放行（不阻止服务起来）。
