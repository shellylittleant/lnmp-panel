# 06 模板机制设计

> docs/03：所有配置项统一采用模板形态。官方模板 + 用户任意一次与现有模板不同的输入即成新模板。模板本身可原文编辑。任何配置都有可视化表单和原文编辑两条路。手改文件后面板要能读回，不能崩、不能覆盖。

模板是核心数据结构，不是某个功能的附属。站点、伪静态、301、SSL 片段、php.ini、FPM pool、nftables、my.cnf、logrotate 都走同一套。

## 1. 类型

| type | 用于 | 阶段 | 表单主要字段（原文始终可编辑整份） |
|---|---|---|---|
| `nginx_site` | server 块 | 2 | 域名、根目录、PHP 上游、HTTP/2、访问限制、防盗链、反代目标 |
| `nginx_rewrite` | 伪静态片段 | 2 | 规则名；内置 WordPress / ThinkPHP / Laravel / 空 |
| `nginx_redirect` | 301 片段 | 2 | from → to |
| `nginx_ssl` | 证书片段 | 2 | cert/key 路径、HSTS |
| `nginx_catchall_404` | 备机兜底 | 7 | 无变量 |
| `php_ini` | php.ini | 3 | upload_max_filesize、memory_limit、max_execution_time、opcache.* |
| `php_fpm_pool` | pool | 3 | user、listen、pm、pm.max_children |
| `mysql_cnf` | 面板托管 my.cnf 片段 | 3 | 连接数、缓冲、慢查询开关 |
| `nftables` | 完整规则集 | 4 | 策略、开放端口、SSH/面板端口、IP 集合、是否公网 80/443 |
| `logrotate` | 轮转 | 5 | 保留天数、大小 |

新增 type 必须改本表并加官方模板。

## 2. 存储与哈希

见数据模型 `templates` 表。`content_hash` = SHA-256（UTF-8 原文，换行统一 `\n`）。

唯一约束 `(type, content_hash)`：同一内容不建第二条。自动创建时若哈希已存在，站点只改引用 ID。

`origin`：

- `official`：embed，启动同步。不可删、不可改内容。用户「另存」产生 `user` 行，`parent_id` 指向官方。
- `user`：可改名、可原文编辑、可删（无引用时）。

## 3. 渲染

引擎：Go `text/template`，option `missingkey=error`。模板里只用白名单函数：`join`、`quote`、`indent`。禁止任意文件读取函数。

变量由模块提供结构体，不让用户在表单里注入新的函数。原文模式不走引擎，整份写入。

`nginx_site` 变量（字段名稳定，阶段 2 实现时以此为准）：

| 变量 | 含义 |
|---|---|
| `.SiteKey` | 目录/文件名 |
| `.Domains` | 域名列表 |
| `.Root` | 站点根 |
| `.PHPSocket` | 空则静态 |
| `.SSLCert` `.SSLKey` | 空则只 HTTP（仍建议面板只对外 HTTPS 站点；HTTP 用于 ACME 与跳转） |
| `.HTTP2` `.HTTP3` | bool |
| `.Rewrite` | 已渲染的伪静态片段 |
| `.Redirects` | 301 列表 |
| `.AccessAllow` | IP 允许列表 |
| `.BasicAuthFile` | 可选 |
| `.ProxyPass` | 反代目标，空则关闭 |
| `.Hotlink` | 防盗链 referer 列表 |

官方 `nginx_site` 模板用 `{{if}}` 包这些块，所以「界面没勾的项」不会出现在 conf 里；用户仍可用原文写任意指令——不设限。

## 5. 「不同即成新模板」算法

用户点保存（表单或原文）时，服务层：

1. 得到最终文本 `content`（表单则渲染，原文则原样）。
2. 算 `hash`。
3. 查 `(type, hash)`：
   - 已有：把资源的 `*_template_id` 指过去。
   - 没有：插入 `origin=user`，`name` = `用户-<日期时间>`，`parent_id` = 保存前的模板 ID（可空）。界面随后允许改名。
4. 写盘、校验、应用。
5. 更新 `last_written_hash`。

不弹窗阻断。改名是可选的后续动作，避免打断「只想改一个值」的路径。列表里能看到自动名，可改成有意义的中文名。

## 6. 表单与原文两条路

```
        ┌──────────────┐
        │ 可视化表单    │──渲染──► content ──┐
        └──────────────┘                     │
                                             ▼
                                        写盘 + 校验
                                             ▲
        ┌──────────────┐                     │
        │ 原文编辑      │──原样───────────────┘
        └──────────────┘
```

- 表单保存：`raw_mode=0`，之后打开用变量填表单；同时提供「查看渲染结果」。
- 原文保存：`raw_mode=1`，之后打开以磁盘文本为编辑器内容；表单字段只读提示「当前为原文模式」，提供按钮「恢复为模板渲染」（会覆盖磁盘，需二次确认）。
- 模板库页：对用户模板直接原文编辑模板本身（改的是库，不影响已 raw_mode 的站点，直到该站点再选这块模板）。

## 7. 手改读回（漂移）

面板不是 conf 的唯一写者。用户 SSH 上去改了文件时：

1. GET 详情必读磁盘，算哈希。
2. 与 `last_written_hash` 不同 → `drifted=true`。
3. 界面顶部中文警告：「磁盘上的配置与面板上次写入不一致，已显示磁盘内容。保存将以你现在提交的内容覆盖磁盘。」
4. PUT 若 drifted 且请求未带 `force=true` → `409 conflict`。前端勾选确认后带 force。
5. 保存成功后哈希对齐，`drifted=false`。若 force 保存的内容与原模板不同，走第 5 节算法生成新用户模板，并视情况进入 raw_mode（无法从官方模板变量还原的，进 raw_mode）。

禁止的行为：

- 后台静默用数据库覆盖磁盘。
- 解析失败就 panic 或清空 conf。解析/渲染失败：保留磁盘文件，API 返回中文错误。

## 8. 导出导入

导出 JSON：

```json
{
  "type": "nginx_rewrite",
  "name": "WordPress-改",
  "content": "..."
}
```

导入一律变成 `origin=user`。不信任文件里的 official 标记。哈希重复则跳过并返回已有 ID。

## 9. 校验责任

模板机制不管语义校验，由领域模块在写盘前调用：

| type | 校验 |
|---|---|
| nginx_* | 写入临时文件或目标文件后 `nginx -t` |
| php_ini / pool | `php-fpmX.Y -t` |
| nftables | `nft -c -f` |
| mysql_cnf | 语法不强制；应用后若 mysqld 起不来用备份回滚 |
| logrotate | `logrotate -d` |

校验失败：不 reload / 不 `nft -f`，磁盘回到备份，API 返回校验器 stderr（截断到合理长度，中文包裹）。

## 10. 与热备、迁移

模板库整表同步。官方模板两边启动都会 embed 同步，冲突按哈希去重。用户模板按哈希合并，ID 可以不同，站点记录在同步时改映射到目标机 ID。迁移模块负责这张映射表，不在模板包里做网络。
