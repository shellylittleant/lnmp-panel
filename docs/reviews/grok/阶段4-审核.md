## 1. 结论：打回

防火墙的骨架是对的：独占规则集、`flush ruleset` 原子替换、`nft -c` 先校验、草稿与开机文件分离、确认窗口、运维 IP 不进封禁集合，这些都实现了，执行者的验证脚本也确实跑通了"应用坏规则后超时回滚"。

但确认窗口这道保命机制有两个漏洞，都在特权容器里复现，都会把运维锁在服务器外面：**回滚是叠加而不是替换**，坏规则里只要有一条显式 drop，回滚就无效；**确认窗口内面板重启后没有任何东西再去回滚**，坏规则永久生效直到机器重启。执行者的验证脚本用的坏规则恰好没有显式 drop，所以看起来回滚成功了。

这是审核前就明确要求做对抗性验证的阶段，两个漏洞都必须修复后重审。

阶段 3 的 G1～G7 已抽查 G1、G2、G3 三项的实现，落地正确。

## 3. 问题清单

### 严重（必须修复，修复后重审）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| S1 | **回滚是叠加不是替换。** `dumpLive` 保存的是 `nft list ruleset` 的原样输出，不含 `flush ruleset`。`Rollback` 用 `nft -f` 加载它时，同名表和链已存在，旧规则被追加到坏规则后面。坏规则里任何一条显式 drop 都排在前面，回滚等于没回滚。 | 备份文件第一行写 `flush ruleset`，再接 dump 内容。加单元测试断言备份文件以 `flush ruleset` 开头；容器测试改用含显式 drop 的坏规则（本审核第 2 节的规则原文），断言超时后 22 与面板恢复。 |
| S2 | **确认窗口内面板重启，坏规则永久生效。** 定时器只在进程内，`firewall_state.pending_backup` 落了库但启动时没人看。面板崩溃、`systemctl restart`、点"重启面板"都会触发。 | 面板启动时（`Run` 里防火墙服务初始化后、HTTP 监听前）检查 `pending_backup`：非空则立即用它回滚（含 S1 的 flush），清空 pending，写一条审计。容器测试：应用坏规则 → 杀进程 → 重启 → 3 秒内 22 恢复。 |

### 一般（必须修复，随严重项一起重审）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | **三份官方模板都没有放行 ICMP。** `policy drop` 下 ICMPv6 被丢，IPv6 的邻居发现失效，有 IPv6 地址的机器 IPv6 直接断；ICMPv4 被丢，ping 不通、路径 MTU 发现失效。 | 在 `ct state established,related accept` 之后加 `meta l4proto { icmp, ipv6-icmp } accept`，可配 `limit rate`。三份模板同改。 |
| G2 | **SSH 端口只会假定 22。** sshd 改过端口的机器，表单默认值就是错的；确认从面板发起，运维不会发现 SSH 已断，直到下次需要 SSH。 | 表单默认值从 `/etc/ssh/sshd_config` 与 `sshd_config.d/*.conf` 的 `Port` 指令取，多个则全部放行；`Apply` 前检查 `/proc/net/tcp` 与 `tcp6` 里是否有进程在 `SSHPort` 上 LISTEN，没有则拒绝并提示"SSH 端口 X 上没有服务在监听，请核对"，带 `force` 可越过。 |
| G3 | `Ensure()` 在开机文件缺失时会直接写一份带 hook、policy drop、SSH 假定 22、且不放行 80/443 的规则集当开机文件（`normalize` 没给 `PublicHTTP` 默认 true）。用户没点过应用，重启就按它加载。 | 开机文件缺失时只写占位空表（与 install.sh 一致），带 hook 的规则集只能经确认写入。`normalize` 的 `PublicHTTP` 默认 true。 |
| G4 | 验证脚本只覆盖了"没有显式 drop 的坏规则"这一种情形，恰好绕过 S1；也没有覆盖窗口内重启。 | 脚本增加两个场景：含显式 drop 的坏规则超时回滚；窗口内杀进程重启后自动回滚。这两个场景以后每个涉及防火墙的阶段都要跑。 |
