## 3. 问题清单

### 严重（必须修复，修复后复查）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| S1 | **重启接口会让面板永久下线。** `handleRestart` 以 `os.Exit(0)` 退出，而 `lnmp-panel.service` 是 `Restart=on-failure`，干净退出不会被拉起。 | 单元改为 `Restart=always`（`systemctl stop` 仍然不会被拉起，不影响手动停止），并在 `[Unit]` 加 `StartLimitIntervalSec=60`、`StartLimitBurst=5`，避免 Docker 检测拒绝启动时每 2 秒无限循环。`handleRestart` 保持现状即可。 |
| S2 | **保存运维白名单可以把自己锁在外面。** `PUT /settings` 不检查调用方 IP 是否在新白名单内，保存后当前会话和登录接口立即 403，只能 SSH 改库。违反 docs/07"防止把自己锁在外面"的原则。 | `Settings.Apply` 或 handler 增加校验：新列表非空时，调用方 IP 必须命中，否则返回 400 中文错误"当前 IP 不在新白名单内，拒绝保存"。加测试覆盖这一条。 |
| S3 | **已开启 TOTP 时重新 setup 会静默关闭 TOTP。** `SetupTOTP` 无条件把 `totp_enabled` 置 0。拿到会话的人不需要密码就能关掉二次验证，绕过了 `disable` 需要密码的设计。 | `SetupTOTP` 在 `totp_enabled=1` 时拒绝，返回 409 并提示"请先关闭 TOTP 再重新绑定"（关闭本身需要密码，路径已存在）。加测试。 |

### 一般（必须修复，随严重项一起复查）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | **install.sh 没有禁用 ufw，也没有确保 nftables 已安装。** 架构 00 第 2 节写明"安装时 disable ufw"。Ubuntu 默认装有 ufw，云镜像上偶有启用；ufw 与面板独占的 nftables 规则集共存会互相覆盖。 | 安装脚本中：若存在 `ufw` 则 `ufw --force disable` 并 `systemctl disable --now ufw`；若 `/usr/sbin/nft` 不存在则 `apt-get install -y nftables`。 |
| G2 | **install.sh 不可重复执行。** 第二次运行时 `bootstrap` 因管理员已存在而失败，`set -e` 使脚本中止，后面的 nftables 与 systemd 步骤不再执行。升级二进制就得靠这个脚本，必须幂等。 | 若 `/etc/lnmp-panel/panel.json` 已存在则跳过 bootstrap，只更新二进制与单元文件并 `systemctl restart`，最后打印 install.info 的内容。 |
| G3 | **改 `bind_mode` 不生效。** 报告问题 1 的答复是：**要**。保存 `bind_mode` 时同步改写 `panel.json` 的 listen 主机部分（`0.0.0.0` 与 `127.0.0.1` 互换，端口不变），返回 `need_restart=true`，前端提示点"重启面板"。 | settings 服务需要拿到配置路径与 `SaveConfig`；加测试读回文件确认 listen 已改。 |
| G4 | **systemd 单元缺 `UMask=0077`。** 现在主库与密钥靠代码逐个 chmod，任何遗漏都会以默认权限落盘。 | `[Service]` 加 `UMask=0077`。 |
| G5 | **审计 action 格式与架构 04 不一致。** 架构写"资源.动词"（如 `site.create`），实现是 `METHOD /path`。 | 接受实现（自动生成、不会漏），改架构 04 第 1.2 节说明为 `METHOD path`，前端筛选按此。 |
| G6 | **`X-Request-Id` 采信客户端头写入审计。** 客户端可往审计日志塞任意字符串。 | 一律服务端生成，忽略客户端传入。 |
| G7 | **迁移器用字符串替换剥掉 001 里的 `schema_migrations` 建表语句。** 能跑，但脆弱。 | `001_init.sql` 删掉这段建表，`Migrate()` 删掉替换逻辑。 |
