## 2. 问题清单

### 严重（必须修复，修复后真机重跑 H7 到 H11、H14）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| S1 | **主机记录的备机地址是备机的主机名，不是可达地址。** 配对时备机把 `advertisedURL()` 发给主机，其中主机部分取自 `os.Hostname()`，在云上是 `VM-0-10-ubuntu` 这类内网名，主机解析不了。双容器测不出来是因为 Docker 内置 DNS 能解析容器名。 | 主机侧记录备机地址时，主机部分一律用**这次配对请求的来源 IP**（`RemoteAddr`），端口与前缀由备机在握手里告知；不再使用主机名。备机侧记录主机地址时用用户填写的 URL 原样。加测试：握手后 `peers.address` 的主机部分是 IP。双容器脚本加断言：A 记录的 B 地址不含容器名。 |

### 一般（必须修复，随 S1 一起）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | 主机角色下 `systemctl start lnmp-panel` 只起面板，nginx 与 mysql 不跟着起。drop-in 只写了 `After=`，它只管顺序不管拉起；整机重启时三者都是 enabled 所以没问题，但运维手动 `stop` 三个服务再 `start lnmp-panel` 就只有面板。 | 主机角色的 drop-in 目录里给 `lnmp-panel.service` 也加一份 drop-in：`Wants=nginx.service mysql.service`。退出主机角色时一起删。 |

### 不改

| 项 | 说明 |
|---|---|
| 增量同步的 `mode` 值是 `incr` 不是 `incremental` | 与架构 04 一致，是内部 API 取值，界面上显示的是中文"增量同步"。不改。 |
