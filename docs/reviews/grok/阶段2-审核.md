## 3. 问题清单

### 严重（必须修复，修复后重审）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| S1 | **面板装完 nginx 后，所有 nginx 操作都被跳过。** `app.go` 里 `sites.SkipNX = !ngx.Installed()` 在进程启动时算一次，此时 nginx 还没装，于是之后建站、改 conf、签证书都不做 `nginx -t`、不 reload。站点不上线，坏配置也照单全收。执行者的验证脚本在建站后自己调了一次 `nginx`，把问题盖住了。 | 每次需要时实时判断 nginx 是否已安装（`Installed()` 调用放进 `TestAndReload` 内部），去掉启动期缓存的 `SkipNX`。测试专用的跳过开关只允许显式设置，不允许从环境推断。验证脚本改为：装完 nginx 后由面板负责启动或 reload，脚本**不得**再手动执行 `nginx`。 |
| S2 | **HTTP-01 在生产环境必然失败。** 挑战文件目录 `/var/lib/lnmp-panel/acme-www` 的父目录是 0700 root，nginx worker 以 www-data 运行，无法穿越，返回 403。 | 挑战目录移到 `/var/www/.acme-challenge/`（0755，属主 root 即可），nginx 模板与 `ssl` 模块同步改路径。加容器测试：写一个 token 文件后用 curl 以 www-data 视角取回 200。 |
| S3 | **证书续期会触发 Let's Encrypt 限流。** 每次签发插入新行、旧行不删，`RenewDue` 按 `expires_at <= 30 天后` 选行，旧行永远命中，每天重签一次直到被限流（同一域名每周 5 张）。 | 签发成功后删除该站点的旧行与旧文件，或 `RenewDue` 只看每站点最新一行。加单元测试：签发两次后表里只剩一行。 |
| S4 | **删除有证书的站点失败且留下半残状态。** `certificates.site_id` 外键无 `ON DELETE`，删站点撞外键；但删库之前 conf 与软链接已经删掉。 | 003 迁移把外键改为 `ON DELETE CASCADE`（SQLite 需重建表），或在删站点前先删证书行；同时删除证书文件目录。整个删除流程改成先校验、再改数据库、最后动磁盘，任何一步失败前面的都回滚。 |
| S5 | **`purge_files` 会删除任意目录。** 根目录是自由输入，purge 时直接 `RemoveAll`。 | purge 只在根目录位于 `/var/www/` 之下且不等于 `/var/www` 本身时执行，否则返回 400「根目录不在 /var/www 下，请手动清理」。加测试。 |
| S6 | **域名、根目录、跳转、反代等字段无校验，可注入 nginx 指令；建站失败不回滚。** 域名 `evil.test { }` 让 `nginx -t` 永久失败，数据库行与 `sites-enabled` 软链接都留在原地，后续所有站点操作全部失败。 | 域名只允许 `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)+$`（含 punycode）；根目录必须是绝对路径、`filepath.Clean` 后不变、不含空白；跳转路径、反代目标、basic auth 文件路径、防盗链域名一律拒绝空白、`;`、`{`、`}`、换行。`Create` 改为：先校验、先渲染、先 `nginx -t`（写临时文件或写后测），全部通过再插库；任一步失败删除已写文件与软链接。加测试覆盖注入输入被拒绝、失败后无残留。 |

### 一般（必须修复，随严重项一起重审）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | 原文模式站点上做表单保存会静默按模板重写。架构 06 第 6 节写的是原文模式下表单只读、恢复模板需二次确认。 | `Update` 在 `raw_mode=1` 时拒绝并返回 409「站点处于原文模式，请先恢复为模板渲染」；前端在原文模式下禁用表单保存按钮，提示文案同步改。 |
| G2 | 每次表单保存都把**渲染后的完整 conf** 存成一条用户模板，模板库被站点实例污染。这是架构 06 第 5 节措辞的问题，审核者阶段 0 漏看。 | 修订架构 06 第 5 节："不同即新模板"只对**用户直接编辑的文本**生效，即原文保存与模板库编辑；表单保存只改变量，不产生模板。`apply` 里去掉 `EnsureUser`，`PutRaw` 保留。 |
| G3 | ACME 签发后 `notAfter` 写死 90 天，不是证书真实到期时间。 | 解析返回的叶子证书取 `NotAfter`。 |
| G4 | `RenewDue` 第一个站点续期失败就返回，后面的不续。 | 逐站点续，失败记日志并继续。 |
| G5 | `nginx_ssl` 模板里 server 级 `if ($scheme = http) { return 301 }` 会把 ACME 路径也跳到 https。Let's Encrypt 目前容忍跳转，但依赖对方行为。 | 跳转改到 `location /` 级，或把 80 拆成独立 server 块只放 ACME 与跳转。 |
| G6 | `TestAndReload` 在 `-s reload` 失败时直接执行 `nginx` 启动新 master，绕过 systemd；reload 的错误也被吞掉。 | 有 systemd 时用 `systemctl reload nginx || systemctl start nginx`；无 systemd 才直接启动。任何一步失败要把 stderr 带回错误信息。 |
| G7 | 建站时数据库行先于磁盘操作写入，`ensureRoot` 或渲染失败都留下孤儿行。 | 与 S6 一起改成先做磁盘和校验，最后写库；或用事务包住并在失败时回滚。 |
| G8 | umask 077 下站点目录 700、文件 600。nginx 能读只是因为属主恰好是 www-data；SFTP 用户、非 root 的备份和 rsync 都读不了。架构 00 第 5.2 节写的是 755/644。 | `ensureRoot` 显式 `Chmod` 0755 与 0644，不依赖进程 umask。 |
| G9 | 模板导入忽略 `name`。 | 哈希不存在时用给定名字建；已存在返回已有 ID。 |
| G10 | 前端原文模式提示文案"表单保存会按模板重写"与架构矛盾。 | 随 G1 一起改。 |

### 建议

| 编号 | 建议 |
|---|---|
| B1 | `listen 443 ssl http2` 写法在 nginx 1.25.1 起标记废弃，Ubuntu 26.04 的 nginx 会告警。24.04 的 1.24 不支持 `http2 on;`，暂时保留，版本下限上移时再换。 |
| B2 | ACME 挑战 token 文件用完不删，会堆积。签发结束后清理。 |
| B3 | 模板创建与导入校验 `type` 在枚举内。 |
| B4 | `apply` 与 `PutRaw` 对同一站点没有互斥，并发保存会交错写盘。按站点加锁。 |
| B5 | ACME 自动接受服务条款，设置页或首次签发时提示一次。 |
| B6 | 验证脚本要在 `umask 077` 下启动面板，模拟 systemd 单元的实际环境，否则权限类问题测不出来。 |

## 5. 一句话给执行者

本阶段的教训是验证脚本替代了被测对象的职责：脚本自己启动了 nginx，于是"面板建站后站点可用"从来没有被真正测过。以后每个阶段的验证脚本只准做用户会做的动作，不准替面板补操作。
