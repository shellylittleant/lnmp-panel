## 1. 结论：打回

真机第一轮的价值很大：systemd 拉起、reboot、Let's Encrypt 真签发、防火墙确认与回滚、重启恢复在真实系统上全部通过，说明容器里验证过的东西基本站得住。但暴露出一个容器测试从未触发的致命缺陷：**只要建过站点，面板重启后立即永久卡死**。审核者已在容器复现并定位根因。

## 2. 审核者的复现

| 场景 | 现象 |
|---|---|
| 0 个站点，`GET /sites` | 200 |
| 建 2 个站点后 `GET /sites` | 8 秒无响应；随后**任何**接口都无响应，包括 `GET /auth/session` |
| 站点存在时重启面板 | 启动 3 秒后登录接口无响应 |

根因：`store.Open` 设了 `SetMaxOpenConns(1)`，而 `site.List()` 在 `rows.Next()` 循环里调用 `s.Get(id)` 发起第二个查询，第二个查询等待唯一连接，唯一连接被未关闭的 `rows` 占着，死锁。启动时 `log.aggregate` 任务立即执行，它调用 `Sites()`，于是有站点的机器一启动就死。`mysql.ListUsers()` 里的 `userDBs()` 是同一个模式。真机报告里"对 sqlite 做 WAL checkpoint 并杀进程后恢复"只是恰好在死锁前抢到了一次请求。

## 3. 问题清单

### 严重（必须修复，修复后重审）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| S1 | **SQLite 单连接 + 遍历结果集时嵌套查询 = 死锁，有站点的机器重启即失效。** | 两件事都做：(1) 全仓库排查"`rows` 未 Close 时再发查询"的模式，`site.List`、`mysql.ListUsers` 至少两处，改为先收集 ID 再逐个查；(2) `SetMaxOpenConns` 改为 4，WAL 模式下多个读连接并行，写由 `busy_timeout` 排队。加回归测试：用 `MaxOpenConns(1)` 打开库，建 2 个站点后调用 `List()`，2 秒内必须返回；`ListUsers` 同样。容器验证脚本加一步：建站后重启面板，登录接口 3 秒内 200。 |

### 一般（必须修复，随 S1 一起重审）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | **"恢复为模板渲染"恢复不了。** 原文保存时 `PutRaw` 把站点的 `nginx_template_id` 改绑到了刚生成的用户模板（内容就是那份原文），`UseTemplate` 用它重新渲染，结果还是原文。真机 3.3 首次失败、重建站点才通过，根因在此。默认 index.html 挡住 index.php 是同一根因的表现，不单独处理。 | `PutRaw` 不改 `nginx_template_id`，用户模板只入库供模板页复用；`UseTemplate` 用站点原来选的模板渲染。若原来的模板已被删，退回官方"PHP 站点"或"静态站点"。加测试：原文保存后 use-template，渲染结果含官方模板特征且不含原文标记。 |
| G2 | **`systemctl restart` 常以失败退出。** 收到 SIGTERM 后 `Shutdown` 只给 5 秒，SSE 跟随连接最长 4 分钟不断，超时后 `Run` 返回错误、进程退出码 1。`Restart=always` 把它掩盖了，但每次重启都在日志里留一条失败。 | `Shutdown` 超时后调用 `Close()` 强制关闭并以 0 退出；SSE 与其他长连接处理器使用随服务器关闭而取消的上下文（`BaseContext` 或关闭钩子），收到关闭信号立即结束。 |
| G3 | **运维白名单没有本机豁免，也没有从 SSH 恢复的正规入口。** 出口 IP 一变就 403；`127.0.0.1/32` 也要显式加，本机脚本和后续热备的对端查询都会撞上。 | 回环地址始终放行，不受白名单限制；增加命令行子命令 `lnmp-panel whitelist show`、`set <cidr,...>`、`clear`，从 SSH 直接改库，不用手写 sqlite；设置页白名单输入框旁加一句提示："出口 IP 变化会被拒绝，可 SSH 执行 lnmp-panel whitelist clear 恢复"。 |
