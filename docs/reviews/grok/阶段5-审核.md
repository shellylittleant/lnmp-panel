## 3. 问题清单

### 严重（无）

### 一般（必须修复）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | **日志查询和统计把整个文件读进内存。** `readTail` 用 `os.ReadFile` 读完再截末尾 2 MB；`StatsLive` 与 `AggregateHour` 把整份 access.log 读成字符串再按行切，内存约为文件大小的 5 倍。logrotate 一旦失效（见 G3）日志可达数 GB，面板会被 OOM 杀掉。 | `readTail` 用 `Seek` 从文件末尾读固定字节；统计改为 `bufio.Scanner` 逐行流式聚合，不持有整文件；统计与小时聚合设读取上限（如末尾 256 MB）并在结果里标注"已截断"。加测试：构造 50 MB 文件，断言查询后进程 RSS 增量小于 20 MB。 |
| G2 | **cron 名称可注入任意 crontab 行**，调度表达式范围不校验。名称写进 `# id=.. name=..` 注释行，换行即断开注释。 | 名称拒绝 `\n`、`\r`，并把 `#` 之外的字符限制为可打印字符；调度五段逐段校验取值范围与 `*`、`,`、`-`、`/` 语法；命令中的 `%` 写入 crontab 时转义为 `\%`。创建流程改为先校验、再写 crontab、成功才插库，写失败不留孤儿行。加测试覆盖注入名称与 `99 * * * *` 被拒。 |
| G3 | **logrotate "接管"与发行版配置重叠**，daily 任务每天报 duplicate 错误；php-fpm 与 MySQL 的日志轮转后进程仍写旧文件。 | 写入面板配置时把 `/etc/logrotate.d/nginx`、`php*-fpm`、`mysql-server` 改名为 `.disabled`（同 www.conf 做法），卸载脚本还原；面板模板的 postrotate 对每个 `php*-fpm` 发 USR1（读 `/run/php/php*-fpm.pid`），MySQL 用 `mysqladmin --defaults-extra-file=面板cnf flush-logs`。容器测试：装 nginx 后 `logrotate -d /etc/logrotate.conf` 无 error。真机清单加一项：手动 `logrotate -f` 后 nginx、php-fpm、mysql 仍在写新文件。 |
| G4 | 调度器在一个循环里顺序执行所有任务。`ssl.renew` 走 ACME 可能耗时数分钟，`log.aggregate` 读大文件也慢，期间 `metrics.sample` 停摆，指标出现空洞。 | 每个任务独立 goroutine 执行，同一任务未结束不重入；`List()` 增加"运行中"状态。 |
