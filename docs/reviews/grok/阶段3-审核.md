## 3. 问题清单

### 严重（无）

### 一般（必须修复，阶段 4 报告注明 commit）

| 编号 | 问题 | 修复要求 |
|---|---|---|
| G1 | **删库接口不看库是谁的。** `sys` 被实测删除；任何面板未纳管的库也能一条请求删掉。`mysql`、`performance_schema` 靠服务器自身拒绝，不应依赖。 | `DropDB` 只允许删 `mysql_databases` 表里有记录的库；`mysql`、`sys`、`information_schema`、`performance_schema` 无论如何拒绝并返回 400「系统库不可删除」。未纳管的库提示「该库非面板创建，请手动处理」。加测试。 |
| G2 | **密码走命令行参数。** `CREATE USER ... IDENTIFIED BY`、`ALTER USER`、root 初始化都用 `mysql -e <语句>`，语句在进程列表中对本机任何用户可见，包括以 www-data 跑的 PHP。 | 改为通过 stdin 传 SQL（`exec.RunIO` 已有），`argv` 不得含密码。加测试：断言 Runner 收到的 argv 里没有 `IDENTIFIED BY`。 |
| G3 | **导出把整份 dump 装进内存再塞进 JSON。** 架构 04 写的是"返回 SQL 流或生成文件再下载"。几百 MB 的库会把面板打爆。 | `mysqldump` 的 stdout 直接流到 HTTP 响应，`Content-Type: application/sql`、`Content-Disposition: attachment`；前端改为下载链接。`exec` 包加一个 stdout 为 `io.Writer` 的执行方式。 |
| G4 | 可通过面板创建 `root`、`mysql.sys` 等保留名的账号。 | 用户名黑名单：`root`、`mysql.sys`、`mysql.session`、`mysql.infoschema`，返回 400。 |
| G5 | 安装不存在的 PHP 版本（8.9）会先返回 job 再失败。`List()` 已经知道哪些版本可装。 | `StartInstall` 先查可装列表，不可装直接 400 not_supported，不建 job。 |
| G6 | MySQL 重启失败时错误信息为空（"启动 mysqld 失败： "）。 | 失败时附带 `/var/log/mysql/error.log` 末尾 20 行（截断到 2000 字）。 |
| G7 | `env/install` 把 PHP PPA 和 MySQL 官方源绑在一个任务里。arm64 上 PPA 成功、MySQL 无包，整个任务显示"失败"，用户看不出 PHP 其实已经可装。 | 拆成两个任务：`POST /env/php/repo`（PPA）与 `POST /env/mysql/install`（官方源 + 安装）。架构 04 同步改。前端环境页两个按钮。 |

### 建议

| 编号 | 建议 |
|---|---|
| B1 | pool 表单里的 `listen` 与站点的 `fastcgi_pass` 强耦合，改了就断。第一版把 `listen` 从表单去掉，固定为 `/run/php/phpX.Y-fpm.sock`，原文模式仍可改。 |
| B2 | 实测官方包的 root 走 auth_socket，面板改密码没有生效但靠 socket 认证照常工作，所以没坏。更稳妥的做法是创建专用账号 `lnmp_panel@localhost` 并只用它，不碰 root。`mysql-root.cnf` 的存在和用途写进 README。 |
| B3 | 保存 my.cnf 会重启 MySQL、断开所有连接，前端保存前要提示。 |
| B4 | `List()` 每次调 `apt-cache search`，概览页每次打开都跑一遍。缓存 60 秒。 |
| B5 | `mysqldBin()` 两个分支返回同一路径，删掉。 |

## 4. 对"需要决策的问题"的答复

| 编号 | 答复 |
|---|---|
| 1 MySQL 官方源无 arm64 包 | **待需求方。** 这是产品决定，不是技术决定。两个选项：(a) 保持现状，arm64 机器不能用面板装 MySQL，等官方补包；(b) arm64 上改用 Ubuntu 自带的 `mysql-server`（8.0，Canonical 维护到 2029 年，符合"≥ 8.0"的下限），amd64 仍用官方 8.4 LTS。审核者倾向 (b)：云上 ARM 实例已经很常见，而 (b) 的代码差异只是换个包名、跳过写源。但它给"拒绝兼容"原则开了一个口子，要需求方点头。未答复前按 (a) 执行。 |
| 2 默认系列 8.4 还是 9.7 LTS | **保持 8.4 LTS。** 9.7 LTS 发布不足半年，PHP 生态对它的兼容还没跑够时间；8.4 支持到 2032 年。下一次版本策略修订时再议。 |
